# 06: 스레드 목록 저장·본문 복원과 연결 장애 복구

**What to build:** 앱을 다시 열면 저장한 스레드 목록을 즉시 표시한다. 스레드를 선택하면 에이전트에서 본문과 기존 맥락을 복원하며, 연결이 끊기면 원인을 확인하고 명시적으로 재시도할 수 있다. 스레드 본문 원본은 에이전트가 소유한다.

**Blocked by:** [05: 작업 중단과 승인 요청 처리](./05-turn-control.md)

Status: done

## 근거와 범위

부모 명세: [Atte 첫 버전 구현 명세](../spec.md). 관련 사용자 스토리: 7, 38–43, 47–48.

04에서 도입한 설치 정보 저장 기반을 스레드 목록과 재연결에 필요한 메타데이터로 확장한다. 메시지·도구 출력·승인 이력 전체를 Atte DB에 복제하지 않는다. 설치·인증 상태와 무관하게 목록을 탐색할 수 있게 하고, 본문 복원에 필요한 관리 화면 연결은 이 티켓에서 통합한다. 프로젝트별 고급 탐색과 미전송 대기 메시지 저장은 07에서 추가한다.

설계 근거: [Zed의 외부 ACP 스레드 관리 조사](../../../docs/research/zed-session-history.md). Zed처럼 목록 메타데이터와 실행 중 본문을 분리하고, 스레드 선택 시 공통 ACP로 본문을 불러온다. 이번 범위의 목록은 Atte가 생성하여 알고 있는 스레드다. `session/list` 미지원이어도 저장한 세션 참조로 load/resume할 수 있어야 하며, 외부 도구에서 만든 세션 가져오기와 에이전트 내부 파일 직접 파싱은 추가하지 않는다.

공통 원칙: macOS 우선, 공통 ACP와 capability 기반 구현, Rust의 공개 스레드 인터페이스 중심 테스트, SolidJS의 FSD 구성. 실연결 검증은 Codex로 한정한다. 필요한 테스트를 먼저 작성하고 기존 동작을 유지한다.

## Acceptance criteria

- [x] 04의 Rust 소유 SQLite 저장소에 마이그레이션을 추가해 작업 폴더, 스레드 ID·제목·고정 에이전트, 원격 세션 참조, 시간과 마지막 중단·오류 상태 등 목록·재연결용 메타데이터를 저장한다. 설치 정보만 있는 기존 스키마에서 설치 산출물·버전을 보존한다. 본문·도구 출력·승인 이력의 영구 사본이나 디스크 캐시는 만들지 않는다.
- [x] 재실행 시 저장된 스레드 목록을 에이전트 연결 전에 표시한다. 설치된 에이전트가 없거나 실행 파일이 사라졌거나 인증이 만료되어도 목록을 탐색할 수 있다. 시작 시 관리 화면으로 강제 이동하지 않으며, 새 스레드 생성 또는 선택한 스레드의 복원에 필요한 준비만 안내한다. 재실행 직후 모든 스레드를 연결하거나 본문을 일괄 로드하지 않는다.
- [x] 사용자가 기존 스레드를 선택하면 연결하고 capability에 따라 `session/load`를 우선 사용해 에이전트의 본문과 맥락을 복원한다. `resume`만 지원하면 기존 맥락을 재개하되 과거 메시지를 표시할 수 없다는 안내를 제공한다. 둘 다 미지원이거나 복원이 실패하면 이유를 보여준다. 본문 복원과 새 prompt 전송은 별개이며 복원만으로 작업을 실행하지 않는다. 기존 세션 실패를 새 세션 생성으로 대체하지 않는다.
- [x] 복원 요청 전에 세션 업데이트 수신을 준비하여 응답보다 먼저 도착하는 replay를 메모리의 본문 모델에 반영한다. 이미 메모리에 열린 스레드는 재사용하고, 재연결 시 이전 본문 뒤에 replay를 덧붙이지 않아 중복을 방지한다. 실패한 복원의 부분 replay를 완전한 기록으로 표시하지 않는다. 동일 스레드의 중복 재개 요청은 하나로 합친다.
- [x] 연결 장애·프로세스 종료·인증 오류를 구분해 표시하며, 사용자의 명시적 재시도로 복구한다. 교체된 연결에서 늦게 도착한 출력은 현재 실행에 적용되지 않는다.
- [x] 본문 복원 또는 재개 시 설치·인증이 필요하면 04의 관리 화면으로 안내한다. 준비 후 기존 스레드로 돌아와 명시적으로 재시도하며 고정 에이전트와 원격 세션 참조를 유지한다. 에이전트 삭제 시에도 이 메타데이터는 보존하고 재설치 후 현재 설치 정의로 재시도한다. 인증 성공만으로 prompt를 전송하지 않는다. 에이전트를 사용할 수 없을 때 본문 열람을 보장하지 않으며, 목록과 복원 실패 이유·재시도 경로를 제공한다.
- [x] 앱 재실행으로 미완료 prompt나 과거 승인 결정을 자동 재전송하지 않는다. 이전 실행 중·승인 대기 상태는 현재 실행 중으로 복원하지 않고 중단을 나타내는 메타데이터로 처리한다. 과거 승인 이력이 replay되어도 유효한 승인 조작으로 되살리지 않는다. 재개되는 것은 기존 맥락이며 중단된 작업 재실행은 별도의 사용자 의도다.
- [x] 테스트용 임시 저장소에서 앱 코어를 재생성해 본문 사본 없이 목록과 세션 참조가 복원되고, 본문은 에이전트 load 후 표시됨을 검증한다. 본문·도구 출력·승인 이력이 DB에 저장되지 않음과 설치 정보 보존 마이그레이션을 확인한다. 모의 에이전트로 load 지원, resume만 지원, 둘 다 미지원, list 미지원, 인증 오류, 연결 실패, 조기·부분 replay, 중복 load, 늦은 출력을 재현한다. 에이전트 부재 시 목록 접근과 관리 화면·재설치를 통한 복구도 검증한다.
- [x] Solid 테스트로 목록 접근, 본문 로딩·실패, resume만 지원할 때 안내, 관리 화면 왕복과 명시적 재시도를 확인한다. Codex 프로세스와 앱 코어 재시작 후 load로 과거 본문을 불러오고, 과거 내용을 다시 제공하지 않은 새 질문에 이전 맥락이 유지됨을 확인한다. 관련 검사와 빌드를 통과한다.
