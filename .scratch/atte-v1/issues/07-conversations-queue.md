# 07: 프로젝트별 동시 대화와 대기 메시지

**What to build:** 작업 폴더별로 여러 대화를 만들고 전환하며 독립적으로 실행한다. 작업 중 남긴 대기 메시지는 저장하고 정상 완료 후 순서대로 전송한다.

**Blocked by:** [06: 대화 목록 저장·본문 복원과 연결 장애 복구](./06-history-resumption.md)

Status: complete

## 근거와 범위

부모 명세: [Atte 첫 버전 구현 명세](../spec.md). 관련 사용자 스토리: 11–14, 19–23, 25–29, 37, 48.

이 작업으로 확정된 A안의 대화 탐색 UI를 완성하고, 프로젝트 +를 04의 설치·인증 관리 흐름에 연결한다. 06의 메타데이터 저장 기반을 Atte가 소유하는 미전송 대기 메시지까지 확장한다. 대기 메시지 저장은 에이전트가 소유하는 대화 본문 복제와 구분하며 전송 후 로컬 본문 이력으로 보존하지 않는다. 작업 폴더 공유는 파일 충돌 방지를 보장하지 않으며 worktree 격리는 후속 범위다.

공통 원칙: macOS 우선, 공통 ACP와 capability 기반 구현, Rust의 공개 대화 인터페이스 중심 테스트, SolidJS의 FSD 구성. 실연결 검증은 Codex로 한정한다. 필요한 테스트를 먼저 작성하고 기존 동작을 유지한다. UI 기준은 `codex/prototype-ui`의 `b591a6e`, ACP 실행 근거는 `codex/prototype-acp-validation`의 `65023dc16fc7d62e6065082f11e138e4b9f8385d`다. 프로토타입은 설계·검증 근거로 사용한다.

## Acceptance criteria

- [x] 사이드바에 작업 폴더별 대화를 표시한다. 프로젝트 이름 클릭으로 접고 펼치며 화살표로 상태를 나타낸다. 개수 대신 + 버튼으로 해당 폴더의 새 대화를 연다.
- [x] 프로젝트 +는 현재 사용 가능한 선택 에이전트를 사용하고 사용할 수 없으면 준비된 에이전트를 선택한다. 사용 가능한 에이전트가 없으면 04의 관리 화면으로 안내하며 준비 후 원래 작업 폴더에서 새 대화를 시작할 수 있다. 새 대화는 생성 시 에이전트가 고정된다.
- [x] 사이드바 자체의 오른쪽 상단 버튼으로 여닫고, 닫히면 왼쪽 상단에 다시 열기 버튼을 제공한다. 오른쪽 LIVE OVERVIEW 패널은 두지 않는다.
- [x] 같은 폴더의 여러 대화를 동시에 실행하고, 화면 전환 또는 구독 해제가 실행을 중단하지 않는다. 목록에 실행·승인 대기 상태를 표시하며 출력은 해당 대화에만 들어간다.
- [x] 지원되는 동일 연결의 복수 세션을 검증한다. 한 대화 취소 또는 승인 대기가 다른 대화의 진행을 막지 않는다. 공유 연결 장애는 영향을 받는 모든 대화에 표시된다.
- [x] 한 대화에서 turn은 하나만 실행한다. 실행 중 제출한 메시지는 FIFO 대기열에 저장하고 이전 turn이 정상 완료된 뒤에만 다음 메시지를 한 번 전송한다.
- [x] 취소·실패·인증 상실·앱 재실행 시 대기열을 자동 소진하지 않는다. 대화 선택에 따른 load/resume 또는 인증 성공만으로도 소진하지 않는다. 삭제와 전송이 경쟁할 때 이미 전송된 메시지를 미전송으로 표시하지 않으며 메시지를 중복 전송하지 않는다.
- [x] 중단해도 쌓인 대기 메시지는 그대로 남고 자동 전송되지 않는다. 대기 메시지는 입력창 위에 먼저 들어온 항목부터 위에서 아래로 표시한다. 각 항목은 내용과 맨 오른쪽 휴지통 버튼으로 구성하며 전송 전에 삭제할 수 있다. 긴 내용은 말줄임하고 눌러 펼칠 수 있으며 수정 버튼과 별도 제목·전송 안내는 없다.
- [x] 대기열에 남아 있는 메시지는 재실행 후에도 복원하며 자동 전송하지 않는다. 입력창이 승인 UI로 전환되어도 기존 대기 메시지를 잃지 않는다.
- [x] 전송 시도 기록이나 결과 불명 상태를 영속화하지 않는다. 다음 항목을 보낼 때 저장된 대기열에서 먼저 제거하고, 제거 저장에 성공하면 ACP 전송을 한 번 시도한다. 저장 실패 시 전송하지 않는다. 전송 실패 시 자동 재삽입·재전송하지 않고 기존 오류 표시 경로로 알린다. 제거 직후 전송 전에 앱이 비정상 종료되면 해당 항목이 복원되지 않을 수 있으며 이 구간의 무손실 전달은 보장하지 않는다.
- [x] 공개 인터페이스에서 동시 세션, 출력 분리, 취소 격리, 승인 격리, FIFO, 삭제, 영속 복원과 실패 시 전송 억제를 검증한다. 프로젝트 탐색과 대기 메시지 UI, 프로젝트 +에서 에이전트 부재 → 관리 화면 → 준비 → 원래 폴더의 새 대화 흐름도 테스트한다.
- [x] Codex의 두 대화를 실행·전환·취소하고 승인 대기 중 다른 대화 응답을 확인한다. 프로젝트 접기·생성·사이드바·말줄임 배치를 화면에서 확인하고 관련 검사와 빌드를 통과한다.

## Comments

- 2026-09-18 최종 DB 정책: 미출시 단계이므로 `schema.sql` 하나에 최종 구조를 정의하고 스키마 v1을 유지한다. 버전별 마이그레이션과 과거 스키마 fixture를 제거하고 초기화·재열기·큐 보존 테스트로 대체했다. 아래 v3/v4 마이그레이션 설명은 이전 개발 이력이며 현재 적용하지 않는다. 큐 저장 구조 수정 커밋은 기능 커밋에 합쳤다.

- 2026-09-18 용어 정리: `summary()`와 `ConversationSummary`를 `metadata()`와 `ConversationMetadata`로 바꾸고, 대화 상태를 가리키던 `snapshot`은 `conversation`으로 바꿨다. 구독 메시지도 `kind: conversation`과 `conversation` 필드로 통일했다. 저장된 JSON 필드와 DB 스키마는 바뀌지 않는다.

- 2026-09-18 후속 사용자 결정: 큐는 별도 테이블 대신 기존 `conversations` 행의 `queued_messages` JSON 컬럼에 저장한다. DB v4 마이그레이션으로 v3 큐를 메시지 ID·내용·순서 그대로 옮기고 이전 테이블을 제거한다. 빈 큐는 `[]`로 저장하며 대화 행은 유지한다. 전송·중단 정책은 동일하다.
- 후속 검증: v3 데이터 이전·순서 보존·삭제·빈 큐 재복원 테스트를 추가했다. Rust 전체 68개 통과(실연결 4개 제외), Clippy와 포맷 검사를 통과했고 Standards/Spec 리뷰 지적은 없다.

- 2026-09-18 구현 완료: 프로젝트별 사이드바, 원래 폴더로 돌아오는 에이전트 준비 흐름, 목록 상태 구독, 공유 ACP 연결의 세션별 실행, SQLite v3의 미전송 FIFO와 입력창 위 대기 메시지 UI를 추가했다. 큐 제거 저장에 실패하면 전송하지 않으며 취소 의도와 정상 완료가 경쟁해도 다음 항목을 보내지 않는다.
- 검증: 프론트엔드 전체 40개, Rust 전체 67개 통과(실연결 테스트 4개는 기본 실행에서 제외). 타입 검사, Biome, FSD, nightly rustfmt, Clippy 경고 없는 검사를 통과했다. Codex ACP 1.12.0 실연결 테스트를 별도로 실행하여 동일 연결의 두 대화, 승인 대기 중 다른 대화 응답, 취소 격리와 큐 유지까지 확인했다.
- 화면 검증: 실제 앱 컴포넌트를 사용하는 임시 브라우저 프리뷰와 모의 IPC로 프로젝트 접기·+ 생성·대화 전환·사이드바 닫기, 말줄임/펼침, 중단 후 큐 유지와 승인 UI 위 배치를 확인했다. Mac이 잠겨 있어 네이티브 앱 화면의 직접 조작은 확인하지 못했다. 네이티브 패키지 빌드와 실제 ACP 실행은 별도로 검증했다.
- Standards/Spec 리뷰의 두 지적을 해결했다. ID 기반 렌더링으로 새 상태 스냅샷에도 펼침 상태를 유지하고, 제거 저장 실패 시 전송 억제와 재실행 복원 테스트를 추가했다. 재검토 후 남은 코드 지적은 없다.

- 2026-09-18 사용자 결정: 중단 시 대기열을 유지하고 자동 전송하지 않는다. 입력창 위에 FIFO 순서로 쌓고 각 항목 맨 오른쪽에 휴지통 버튼을 둔다. 전송 시도 기록을 저장하는 방식 대신 대기열 제거 저장 후 한 번 전송하는 단순한 방식을 채택한다. 중단 후 명시적인 재개 조작은 아직 확정하지 않았으며 빈 입력창의 Enter를 재개 동작으로 추가하지 않는다.

- 2026-09-18 06의 메타데이터 전용 저장 정책과 정합성을 맞췄다. 미전송 대기 메시지는 Atte 소유이므로 영속화하되, 전송 후 본문 사본으로 보관하지 않는다. 본문 복원·맥락 재개만으로 대기열을 실행하지 않는다.

- 2026-09-17 순서 조정: 기존 06을 07로 이동했다. 기존 07의 프로젝트 +와 관리 화면 연결 조건을 인수하며, 이미 구현된 설치·인증 및 대화 저장 기능과 통합한다.
