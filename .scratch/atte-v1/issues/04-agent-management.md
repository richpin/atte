# 04: Registry 기반 설치·인증과 에이전트 선택

**What to build:** 사용자가 별도 관리 화면에서 Claude·Codex·Antigravity를 설치하고 인증 안내를 따라 준비한 뒤 원하는 에이전트로 대화를 시작한다.

**Blocked by:** [03: 메시지 전송과 스트리밍 응답](./03-message-streaming.md)

Status: done

## 근거와 범위

부모 명세: [Atte 첫 버전 구현 명세](../spec.md). 관련 사용자 스토리: 1–7, 9–11, 41, 49–50.

03의 실행 정의와 대화 흐름에 설치·인증 관리 화면을 연결해 사용자가 앱에서 직접 준비하고 응답까지 확인할 수 있게 한다. 설치 정보에 필요한 정식 영속 저장 기반을 이 티켓에서 도입하고 06에서 대화 저장으로 확장한다. 저장된 대화의 오프라인 열람은 06, 프로젝트 + 연결은 07의 완료 조건이다. 업데이트 자동화, 에이전트 제거 및 지원 대상 확대는 추가하지 않는다.

설치·인증·대화 왕복이 하나의 완료 가능한 경로다. 기존 실행 정의 경계를 유지한 채 설치 결과를 반영할 수 있도록 먼저 정리하되 진행 중인 대화나 구독을 재생성하지 않는다. 승인 요청은 03의 취소 응답을 유지하고, 사용자 승인·작업 중단은 05에서 완성한다.

공통 원칙: macOS 우선, 공통 ACP와 capability 기반 구현, Rust의 공개 대화 인터페이스 중심 테스트, SolidJS의 FSD 구성. 실연결 검증은 Codex로 한정한다. 필요한 테스트를 먼저 작성하고 기존 동작을 유지한다. UI 기준은 `codex/prototype-ui`의 `b591a6e`, ACP 실행 근거는 `codex/prototype-acp-validation`의 `65023dc16fc7d62e6065082f11e138e4b9f8385d`다. 프로토타입은 설계·검증 근거로 사용한다.

## Acceptance criteria

- [x] 공식 ACP Registry를 바탕으로 세 대상 에이전트의 목록과 플랫폼에 맞는 배포를 표시한다. npm 배포와 macOS 바이너리 배포를 필요한 범위에서 처리한다.
- [x] 다운로드·설치 진행, 성공, 실패와 해결 가능한 안내를 표시하고 실제 설치 산출물·해석된 버전을 저장한다. 재실행 후 설치 상태를 복원하며 실패를 설치 성공으로 기록하지 않는다.
- [x] 설치 정보의 저장은 Rust가 소유하며 저장소 경계와 스키마 버전·마이그레이션을 갖춘다. 기존 의존성과 유지보수 상태를 확인해 저장 라이브러리를 선정한다. 이 단계에는 설치 정보에 필요한 스키마만 만들고, 06에서 같은 기반을 확장한다. 나중에 교체할 임시 저장 방식이나 대화·대기열의 선행 구현을 추가하지 않는다.
- [x] 설치·ACP 연결·인증·실행 가능 상태를 구분한다. 세션 생성 성공이나 빈 authMethods만으로 인증 완료라고 판단하지 않는다.
- [x] 인증 안내와 시작은 에이전트가 제공한 방식 및 필요한 에이전트별 호환 처리에 따른다. 실패 후 다시 시도하고 준비된 상태로 돌아오는 UI 흐름이 있다. 자격 증명을 대화 기록이나 로그에 출력하지 않는다.
- [x] 앱 시작 또는 새 대화 시 설치된 에이전트가 없으면 관리 화면으로 안내한다. 현재 대화의 인증 오류 안내에서도 관리 화면을 열고, 인증 후 사용자의 명시적 재시도로 같은 대화에서 연결을 다시 시도할 수 있다.
- [x] 설치 완료 후 앱을 재시작하지 않아도 에이전트 목록과 실행 정의에 결과가 반영된다. 설치한 에이전트를 선택해 작업 폴더의 새 대화를 만들고 자동 연결한다. 기존 대화의 고정 에이전트·실행·구독은 관리 화면 이동이나 목록 갱신으로 바뀌거나 중단되지 않는다.
- [x] 배포·실행·인증 차이는 에이전트별 실행 정의와 adapter에 한정한다. 설치 결과도 기존 공통 ACP 대화 경로를 사용하며 공급자 전용 값을 대화 처리에 추가하지 않는다. 후속 재개·취소·승인 기능도 같은 경계를 사용한다.
- [x] Registry fixture와 제어 가능한 설치·인증 결과로 설치 성공·실패·재시도·재실행·인증 만료·로그인 후 시작을 검증한다. 저장소 재생성과 스키마 마이그레이션, 설치 직후 목록 갱신과 기존 대화 유지도 검증한다. 세 에이전트가 공통 ACP 계약을 사용함을 모의 에이전트로 검증한다.
- [x] 실제 계정 검증은 인증된 Codex로만 수행한다. Claude와 Antigravity의 로그인 의존 항목은 사용자 후속 검증으로 명시하고 미검증을 성공으로 표시하지 않는다.
- [x] 준비된 실행 정의로 시작했던 03의 대화 흐름이 Registry 설치 결과로도 동작한다. 실제 macOS 앱에서 수동 실행 경로 지정 없이 설치·인증 안내 → 폴더 선택 → 자동 연결 → 메시지·스트리밍 → 같은 대화의 후속 응답을 확인하고, 재실행 후 설치 상태 복원과 새 대화도 확인한다. 승인·도구 사용이 필요 없는 Codex 요청으로 검증하고 버전·절차·관찰 결과를 기록하며 관련 검사와 빌드를 통과한다.

### 기존 범위 검증 기록 — 2026-09-17

세 에이전트 대상의 기존 구현에 대한 기록이다. 확장된 ACP 에이전트 관리 시스템의 완료 증거와 구분한다. 기존 별도 파일의 내용을 이 티켓으로 통합했다.

#### 구현과 근거

- [공식 Registry](https://github.com/agentclientprotocol/registry/blob/main/README.md)의 stable CDN index를 사용한다. [배포 규격](https://github.com/agentclientprotocol/registry/blob/main/FORMAT.md)에 따라 npm 패키지와 현재 macOS 플랫폼의 zip 바이너리를 선택한다. Antigravity의 macOS Intel 배포가 없으면 지원하지 않는 것으로 표시한다.
- `b591a6e`의 관리 화면 분리·고정 에이전트·대화 유지 패턴과 `65023dc`의 실제 ACP 관찰을 적용했다. 관리 화면 이동은 대화의 프로세스나 구독을 재생성하지 않는다. 설치 정의 교체도 이미 생성된 대화의 실행 정의를 바꾸지 않는다.
- 저장 라이브러리가 기존 의존성에 없음을 확인했다. [rusqlite 0.40.2](https://docs.rs/crate/rusqlite/0.40.2)는 현재 유지보수되는 SQLite 래퍼이며, 작은 Rust 저장소에 ORM/별도 런타임 없이 트랜잭션과 스키마 마이그레이션을 제공한다. bundled SQLite를 사용하고 `Store`에서 `user_version` 0→1 마이그레이션을 트랜잭션으로 실행한다. 이번 스키마에는 설치 정보만 포함한다. 기존 reqwest 0.13.5를 직접 재사용한다.
- 설치 디렉터리는 앱 데이터 폴더 아래에서 설치마다 고유하게 생성한다. npm은 Registry의 고정 버전과 실제 package.json 버전을 비교하고 로컬 엔트리포인트를 저장한다. 바이너리는 플랫폼 배포 버전과 추출된 경로를 저장하며, Registry가 제공한 SHA-256이 있으면 검사한다. 실패는 설치 성공으로 저장하지 않는다.
- 인증 방식은 [ACP SDK의 안정 v1 타입](https://docs.rs/agent-client-protocol/2.1.0/agent_client_protocol/)과 [Registry 인증 규약](https://github.com/agentclientprotocol/registry/blob/main/AUTHENTICATION.md)을 따른다. Agent 방식은 `authenticate`, Terminal 방식은 제공된 추가 인수·환경으로 macOS Terminal에서 실행하며 종료 코드로 결과를 확인한다. 자격 증명은 UI 대화·앱 로그·설치 DB에 저장하지 않는다.
- Codex `api-key` 호환 안내는 설치된 1.12.0 어댑터의 `CODEX_API_KEY` / `OPENAI_API_KEY` 요구사항을 근거로 한다. 새 키 입력 UI는 추가하지 않는다. 환경 변수가 없는 경우 해결 가능한 안내와 ChatGPT 선택 경로를 제공한다.
- 초기화 성공·세션 생성·빈 인증 방식은 인증 완료의 근거로 사용하지 않는다. 인증 성공 응답 또는 실제 prompt 성공이 인증 근거다. 대화의 인증 만료는 관리 화면에도 반영하며, 로그인 성공만으로 실패한 대화를 자동 재시도하지 않는다.

#### 검증 범위

- Codex: Registry npm 설치, 인증 방법 안내, 기존 로그인으로 응답·후속 응답·재실행 후 새 대화 검증.
- Claude·Antigravity: Registry 배포 선택 및 공통 모의 ACP 계약 검증. 실제 계정 로그인/응답과 실제 Terminal 로그인 완료는 사용자 후속 검증이며 성공으로 표시하지 않는다.

- 대화 기록의 영속 복원, 승인·취소, 큐, 앱 수명주기 확장은 후속 티켓 범위다.
