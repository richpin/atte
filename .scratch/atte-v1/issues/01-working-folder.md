# 01: 작업 폴더 선택과 빈 대화 화면

**What to build:** 작업 폴더를 선택하면 해당 폴더에 연결된 빈 대화 화면을 열 수 있다.

**Blocked by:** None (can start immediately)

Status: done

## 근거와 범위

부모 명세: [Atte 첫 버전 구현 명세](../spec.md). 관련 사용자 스토리: 8–10, 18.

범위는 네이티브 폴더 선택, Rust가 관리하는 로컬 대화 초안, 최소 화면과 좁은 Tauri 명령이다. ACP 프로세스·SDK·스트리밍·구독 시스템·영속 저장·프로젝트 목록은 후속 티켓에서 추가한다. 대화 초안은 실제 제품에서 사용할 상태이며 원격 세션을 생성했다고 표시하지 않는다.

공통 원칙: macOS 우선, Rust 공개 대화 인터페이스 중심 테스트, SolidJS FSD 구성. UI 기준은 `codex/prototype-ui`의 `b591a6e`이며 프로토타입 코드를 그대로 이식하지 않는다. 필요한 테스트를 먼저 작성하고 관련 frontend 검사·타입 검사·테스트와 Rust 검사·테스트 및 빌드를 통과한다. 실제 에이전트 검증은 Codex로 한정한다.

## Acceptance criteria

- [x] 초기 템플릿을 정리하고 폴더 선택과 작은 한 줄 대화 제목·폴더 표시가 있는 최소 화면을 제공한다.
- [x] macOS 폴더 선택으로 경로를 전달하며 사용자가 선택을 취소하면 새 대화를 만들지 않는다. Rust에서 존재하는 디렉터리인지 검증하고 실패를 화면에 표시한다.
- [x] Rust의 대화 생성·조회 인터페이스로 안정적인 앱 대화 ID, 작업 폴더, 에이전트 식별자를 가진 메모리 내 초안을 만든다. 원격 세션 참조는 아직 없으며 UI에 연결 전 상태로 표시한다.
- [x] 에이전트는 준비된 실행 대상의 식별자로 고정한다. 프로세스 실행은 하지 않고 에이전트 목록·설치·인증 관리는 요구하지 않는다.
- [x] 빈 대화 화면의 입력·전송은 연결 전 상태임을 보여주며 메시지를 보냈다고 표시하지 않는다. 메시지 표시 디자인은 03에서 구현한다.
- [x] 공개 인터페이스 테스트로 유효·유효하지 않은 폴더와 초안 조회를 검증한다. Solid 테스트와 macOS 확인으로 폴더 선택·취소·빈 화면 진입을 검증한다.

## Comments

- 사용자의 첫 티켓 축소 요청에 따라 기존 01을 01–03으로 분할했다. 이 파일은 구현 완료가 아닌 준비된 작업을 나타낸다.

- 2026-09-17 구현 완료: Rust `Conversations::create/get`가 UUID·정규화된 작업 폴더·고정 Codex 식별자·연결 전 상태를 가진 메모리 초안을 관리한다. 네이티브 선택창은 Rust의 좁은 `select_working_folder` 명령에서 열며 취소 시 생성하지 않는다. Solid FSD 화면에는 한 줄 헤더, 폴더, 오류 안내, 비활성 입력·전송을 제공한다.
- TDD 검증: Rust 공개 인터페이스 4개(생성·조회·고유 ID, 파일 거부, 없는 폴더 거부, 없는 대화 조회), Solid 화면 5개(선택·빈 화면, 초기 취소, 오류 안내, 기존 대화에서 취소, 선택 중 중복 방지). 최초 실패를 확인한 후 구현했다.
- macOS 배포 앱에서 실제 네이티브 선택창의 취소 시 초기 화면 유지, 저장소 폴더 선택 후 빈 대화 진입, 한 줄 제목·폴더·연결 전 표시와 입력·전송 비활성을 확인했다. `pnpm tauri build --bundles app` 통과. 에이전트 프로세스는 실행하지 않았다.
- 코드 리뷰: 시작 커밋 `1f145bd` 기준 staged diff를 Standards/Spec 두 에이전트가 독립 검토했다. Standards의 오류 타입 `std::error::Error` 미구현 1건은 `thiserror`로 수정했고, Spec 지적은 없었다.
- 최종 검사: `pnpm validate`와 `sh scripts/validate-rust.sh` 통과(Biome, TypeScript, 전체 Solid 테스트, Rust fmt/check/Clippy/전체 테스트). 사용자 확인에 따라 부모 `spec.md`와 기존 Cargo 준비 변경 전체를 구현 커밋에 포함했다.
