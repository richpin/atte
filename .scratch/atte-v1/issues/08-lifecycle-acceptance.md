# 08: 앱 수명주기와 첫 버전 통합 검증

**What to build:** 창을 닫아도 작업이 계속되며, 앱 종료를 요청하면 확인창 없이 진행 중인 작업을 취소하고 상태 저장과 프로세스 정리 후 종료한다. 첫 버전 전체 흐름이 재실행과 함께 일관되게 동작한다.

**Blocked by:** [07: 프로젝트별 동시 스레드와 대기 메시지](./07-threads-queue.md)

Status: implemented — native quit-policy revalidation pending

## 근거와 범위

부모 명세: [Atte 첫 버전 구현 명세](../spec.md). 관련 사용자 스토리: 44–50 및 전체 사용자 스토리 회귀 검증.

04의 설치·인증, 05의 승인·취소, 06의 목록 저장·에이전트 본문 복원, 07의 동시 스레드·대기 메시지가 완료된 제품을 대상으로 하는 수명주기 기능과 최종 통합 검증 티켓이다. 개별 티켓의 테스트와 관리 화면 통합은 각 티켓에서 이미 완료되어야 한다.

공통 원칙: macOS 우선, 공통 ACP와 capability 기반 구현, Rust의 공개 스레드 인터페이스 중심 테스트, SolidJS의 FSD 구성. 실연결 검증은 Codex로 한정한다. 필요한 테스트를 먼저 작성하고 기존 동작을 유지한다.

## Acceptance criteria

- [x] 마지막 창을 닫아도 실행 중인 Rust 작업과 에이전트 연결이 유지된다. 다시 창을 열면 현재 스레드 상태와 이후 스트림이 누락·중복 없이 연결된다.
- [x] 실행 또는 승인 대기 중에도 앱 종료를 요청하면 확인창 없이 정리를 시작한다. 해당 turn과 미해결 승인을 취소한 뒤 종료·중단 상태 메타데이터를 저장한다. 본문·도구 출력·승인 이력을 앱 DB에 복제하지 않는다.
- [x] 앱 종료에서는 관리 대상 자식 프로세스와 진행 중 태스크를 정리한다. 응답하지 않는 프로세스도 종료가 무한 대기하지 않도록 관리 대상에 한정해 정리한다.
- [x] 재실행 시 스레드 목록·작업 폴더·세션 참조·설치 상태·미전송 대기 메시지가 복원된다. 목록 표시에 에이전트 연결은 필요하지 않으며, 사용자가 스레드를 선택하면 06의 capability 정책에 따라 본문·맥락을 복원한다. 중단된 turn, 승인 응답, 대기 메시지는 재실행·load/resume·인증 성공으로 자동 실행하지 않는다.
- [ ] 공개 스레드 인터페이스의 수명주기 테스트와 필요한 Tauri 통합 검증으로 창 닫기, 재열기, 실행 중 확인창 없는 종료, 승인 대기 중 확인창 없는 종료 및 재실행을 확인한다.
- [x] 실제 macOS 앱에서 창 닫기와 완전 종료의 차이를 확인하고 실행 상태·프로세스 정리가 화면 상태와 일치함을 검증한다.
- [x] 실제 macOS 앱에서 Codex의 Registry 설치·인증 안내 → 폴더 선택 → 스레드·스트리밍 → 승인·취소 → 동시 스레드 → 대기 메시지 → 종료·재실행 → 목록 표시 → 에이전트에서 본문 복원 → 새 질문으로 실제 맥락 재개까지 통합 검증한다. 별도 테스트 폴더와 버전·관찰 결과를 기록한다. 관리 화면 이동이 다른 스레드 실행을 중단하지 않는지, 설치·인증 불가 상태에서도 목록 접근과 본문 복원 실패 안내가 유지되는지, 준비 후 명시적 재시도가 가능한지 회귀 검증한다.
- [x] 부모 명세의 사용자 스토리 전체에 구현·자동 테스트·수동 검증 근거를 연결하고 미검증 항목을 구분한다. Claude·Antigravity의 인증된 실사용 확인은 사용자 후속 검증으로 남긴다.
- [x] 확정한 A안의 UI와 접근 가능한 조작을 확인하고 전체 frontend 검사·타입 검사·테스트, Rust 포맷·린트·테스트 및 macOS production Tauri 빌드를 통과한다.
- [x] 프로토타입 전용 시안 선택기·평가 툴바가 제품에 포함되지 않고, worktree 자동 격리나 외부 스레드 가져오기 등 범위 밖 기능을 구현하지 않았음을 확인한다.

## Comments

- 2026-09-18 확인창 제거 구현 후 Rust 전체 검사·70개 테스트와 격리 production 빌드를 통과했다. 실제 Codex 응답 중 Cmd+Q로 확인창 없이 종료되고 하위 프로세스가 정리됨을 확인했다. 재실행 시 Mac 잠금이 감지되어 변경 후 큐 복원·승인 대기 중 종료의 네이티브 재검증은 남겨 둔다.

- 2026-09-18 사용자 결정으로 앱 종료 확인창과 종료 취소 단계를 제거한다. 명시적 종료는 바로 작업 취소·상태 저장·관리 대상 프로세스 정리를 시작하며, 응답 완료를 기다리거나 이미 수행한 파일 변경을 되돌리지 않는다. 창 닫기 시 작업 유지와 재실행 시 자동 실행 억제 정책은 유지한다. 아래 종료 확인·취소 검증 기록은 변경 전 정책의 이력이다.

- 2026-09-18 Mac 잠금 해제 후 남은 네이티브 복구 검증을 완료했다. 설치가 복구된 앱에서 기존 스레드를 선택해 세션 준비 완료, 에이전트 본문과 중단 안내 복원을 확인했다. 입력 시 전송 버튼이 활성화됐고, 기존 대기 메시지는 자동 전송되지 않았다. 검증용 입력은 전송하지 않고 지웠다. 모든 인수 기준을 확인하여 티켓을 완료한다.

- 2026-09-18 수명주기 구현과 자동 검증, Standards/Spec 리뷰 수정을 완료했다. 창 닫기·재열기, 종료 취소·확인, 승인 대기 중 종료, 프로세스 정리 및 재실행을 실제 Codex/macOS 앱에서 확인했다. 프론트엔드 40개, Rust 70개, 실제 Codex 연결 4개 테스트와 production 빌드가 통과했다. [검증 기록](../lifecycle-acceptance.md)에 전체 사용자 스토리 근거와 버전·관찰 결과를 정리했다. 설치 불가 상태의 목록·실패 안내와 설치 복구 후 연결 시작까지 확인했으나 Mac 잠금으로 마지막 준비 완료 화면을 확인하지 못해 해당 통합 검증 항목은 열어 둔다. 기존 개발 DB(v4)는 변경하지 않고 별도 식별자의 v1 앱에서 검증했다.

- 2026-09-18 06의 저장 정책 변경을 반영했다. 재실행 직후 복원 대상은 목록·재연결 메타데이터와 미전송 대기 메시지이며, 스레드 본문은 선택 시 에이전트에서 불러온다. 설치·인증 불가 시 전체 본문 열람 보장 대신 목록 접근과 실패 안내·복구를 검증한다.

- 2026-09-17 순서 조정: 번호는 유지하며 선행 티켓을 새 07(동시 스레드·대기 메시지)로 갱신했다. 새 순서 03 → 04 설치·인증 → 05 승인·취소 → 06 저장·재개 → 07 동시 스레드·대기 메시지 → 08 수명주기 전체를 검증한다.

- 기존 첫 티켓을 세 단계로 나누면서 총 8개 작업으로 번호와 선행 링크를 갱신했다. 첫 티켓의 UI는 최소 스레드 화면으로 제한하며 이후 UI는 해당 기능과 함께 완성한다.
