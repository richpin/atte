# 스레드 응답 상태와 완료 확인

## Problem Statement

여러 스레드에서 에이전트가 동시에 작업할 때 사용자는 첫 응답을 기다리는 중인지, 작업이 진행 중인지, 승인이 필요한지, 응답이 완료됐는지, 오류로 멈췄는지 빠르게 구분해야 한다. 현재 사이드바의 텍스트 상태와 메뉴 버튼만으로는 상태를 간결하게 파악하기 어렵고, 다른 스레드에서 완료된 응답을 아직 확인하지 않았다는 표시도 없다.

## Solution

매 요청의 첫 응답 텍스트가 오기 전에는 대화 영역의 응답 시작 위치에서 에이전트 아이콘이 작게 → 크게 → 작게 움직인다. 사이드바에서는 진행 중인 스레드의 오른쪽 메뉴 버튼 자리를 회전하는 스피너가 차지한다. 승인 요청은 파란 배지, 미확인 완료는 속이 빈 파란 원, 요청·연결·구독 오류는 같은 크기의 주황색 원형 경고 아이콘으로 표현한다.

사용자가 해당 스레드 페이지를 열면 완료를 확인한 것으로 처리한다. 앱 포커스나 스크롤 위치는 확인 조건에 포함하지 않는다. 완료·확인 정보는 앱 실행 중에만 유지하며 재시작하면 초기화한다. 상태 표시 중에도 마우스·키보드·우클릭으로 기존 메뉴를 사용할 수 있다.

## User Stories

1. As an Atte 사용자, I want a 첫 응답 전의 에이전트 아이콘 애니메이션, so that 요청이 처리되고 있음을 알 수 있다.
2. As an Atte 사용자, I want a 응답 텍스트의 시작 위치에 정렬된 대기 표시, so that 응답이 나타날 위치를 알 수 있다.
3. As an Atte 사용자, I want a 매 요청마다 다시 나타나는 첫 응답 대기 표시, so that 후속 요청도 접수 후 진행 중임을 알 수 있다.
4. As an Atte 사용자, I want a 첫 응답 텍스트 수신 시 사라지는 대기 표시, so that 응답을 방해 없이 읽을 수 있다.
5. As an Atte 사용자, I want a 사이드바에서 계속 회전하는 진행 스피너, so that 텍스트 출력과 도구 실행을 포함한 작업 진행을 알 수 있다.
6. As an Atte 사용자, I want a 파란 승인 요청 배지, so that 내 판단이 필요한 스레드를 찾을 수 있다.
7. As an Atte 사용자, I want a 승인 처리 후 진행 표시로 돌아가는 상태 표시, so that 작업이 재개됐음을 알 수 있다.
8. As an Atte 사용자, I want a 중단 처리 중과 중단 완료를 구분하는 표시, so that 중단이 실제로 끝났는지 알 수 있다.
9. As an Atte 사용자, I want a 다른 스레드에서 완료된 응답의 속이 빈 파란 원, so that 아직 확인하지 않은 결과를 찾을 수 있다.
10. As an Atte 사용자, I want a 해당 스레드 페이지를 열면 사라지는 완료 원, so that 이미 확인한 결과가 계속 알림으로 남지 않는다.
11. As an Atte 사용자, I want a 열려 있는 스레드에서 완료된 응답의 즉시 확인 처리, so that 불필요한 미확인 표시가 생기지 않는다.
12. As an Atte 사용자, I want a 설정이나 에이전트 관리 페이지에서는 유지되는 미확인 표시, so that 이전에 선택했던 스레드의 새 결과를 놓치지 않는다.
13. As an Atte 사용자, I want a 실패·연결 오류를 나타내는 주황색 경고 아이콘, so that 정상 완료와 문제 발생을 구분할 수 있다.
14. As an Atte 사용자, I want a 상태 구독 실패 시의 경고 표시, so that 마지막으로 보인 진행 상태를 현재 상태로 오해하지 않는다.
15. As an Atte 사용자, I want a 복구 후 실제 상태로 돌아가는 표시, so that 해결된 오류가 계속 남지 않는다.
16. As an Atte 사용자, I want a 연결·스레드 복원 중임을 설명하는 표시, so that 이를 첫 응답 대기와 구분할 수 있다.
17. As an Atte 사용자, I want a 대기 메시지가 연속 실행돼도 유지되는 진행 표시와 이전 완료 정보, so that 진행 중인 작업과 아직 확인하지 않은 결과를 놓치지 않는다.
18. As an Atte 사용자, I want a 상태 표시 중에도 접근 가능한 스레드 메뉴, so that 완료·오류 표시 때문에 기존 작업을 못 하게 되지 않는다.
19. As an 키보드 사용자, I want a 포커스로 접근 가능한 메뉴와 상태 이름, so that 마우스 없이 스레드를 관리하고 상태를 파악할 수 있다.
20. As an Atte 사용자, I want a 라이트·다크 테마에서 구분되는 상태 표시, so that 어느 테마에서도 진행·완료·오류를 읽을 수 있다.
21. As an 동작 줄이기 설정 사용자, I want a 정적인 대기·진행 표시, so that 애니메이션 없이도 상태를 알 수 있다.
22. As an Atte 사용자, I want a 앱 재시작 시 초기화되는 미확인 완료 표시, so that 이번 실행 중의 새 응답만 완료 알림으로 표시된다.

## Implementation Decisions

### 대화 영역

- 첫 응답은 첫 대화 전체가 아니라 매 사용자 입력에 대한 응답의 첫 텍스트를 뜻한다. 도구 실행이나 승인 요청만 도착한 상태는 첫 응답 텍스트 수신으로 취급하지 않는다.
- 활성 턴에 응답 텍스트가 없고 스레드가 `running`일 때 사용자 메시지 아래의 에이전트 응답 시작 위치에 기존 에이전트 아이콘을 표시한다. 첫 텍스트가 수신되면 제거한다. 텍스트 없이 응답이 종료돼도 제거한다.
- 기존 아이콘 이미지·폴백·테마 처리를 재사용한다. 24px 고정 영역에서 1.4초 주기로 배율 `0.75 → 1 → 0.75`를 반복한다. 확대·축소는 레이아웃 크기와 메시지 간격을 바꾸지 않는다.
- 승인 대기 중에는 아이콘을 정적인 상태로 유지한다. 승인 후 다시 `running`이 되고 텍스트가 아직 없으면 애니메이션을 재개한다. 중단 처리·오류·연결 상태에서는 첫 응답 대기 아이콘을 제거한다.

### 사이드바 표시

| 상태 | 표시 및 종료 조건 |
| --- | --- |
| 연결·스레드 복원 중 | 회전하는 `LoaderCircle`, 연결 중 또는 복원 중 툴팁 |
| 응답 진행 | 회전하는 `LoaderCircle`; 첫 텍스트 이후에도 요청 종료까지 유지 |
| 승인 대기 | 스피너 대신 파란 승인 요청 배지; 승인 후 작업 재개 시 스피너 복원 |
| 중단 처리 중 | 회전하는 `LoaderCircle`, 중단 중 툴팁 |
| 중단 완료 | 스피너 제거, 기존 메뉴 복원; 취소 자체로 정상 완료 원을 만들지 않음 |
| 응답 완료·미확인 | 내부가 빈 파란 `Circle` |
| 응답 완료·확인 | 완료 원 제거, 기존 메뉴 복원 |
| 요청 실패·에이전트 연결 오류·상태 구독 실패 | 주황색 `CircleAlert` |
| 비정상 중단 이력만 있고 현재 오류 없음 | 기존 중단 안내 유지, 정상 완료 원 생성하지 않음 |

- 스피너·완료 원·경고 아이콘은 모두 16px, 동일한 선 두께와 정렬을 사용한다. 스피너는 1초에 한 바퀴 회전한다. 완료 원의 내부는 채우지 않는다.
- 기존 사이드바의 실행 중·승인 대기·연결 오류 텍스트는 새 상태 표시로 대체한다.
- 공용 상태 표시는 공유 UI에 두고 Tailwind와 중앙 스타일 토큰을 사용한다. 파랑은 기본 `#2563EB`, 다크 `#3B82F6`; 주황은 기본 `#C2410C`, 다크 `#FB923C`를 사용한다. 승인 배지는 같은 파란색 계열의 연한 배경과 텍스트로 표현한다.
- 승인 배지의 영어 문구는 `Ask for Approval`, 한국어 문구는 `승인 요청`이다. 상태별 접근성 이름과 툴팁을 제공한다.
- 상태 우선순위는 오류 → 승인 요청 → 연결·응답·중단 진행 → 미확인 완료 → 메뉴다. 우선순위가 높은 표시가 이전 완료 원을 가려도 완료·확인 정보는 보존한다.
- 여러 승인 요청이 있으면 마지막 미처리 승인 요청이 해소될 때까지 배지를 유지한다. 승인 명령 성공만으로 작업 재개를 추측하지 않고 구독 상태를 따른다.
- 스피너·완료 원·오류 아이콘은 메뉴 버튼 자리에 표시한다. 행에 마우스를 올리거나 키보드 포커스를 주면 해당 아이콘 대신 메뉴 버튼을 표시한다. 승인 배지는 유지하고 별도의 메뉴 공간을 확보한다. 우클릭 메뉴도 유지한다.
- OS의 동작 줄이기 설정에서는 회전과 확대·축소를 사용하지 않는다. 정적 아이콘과 상태 이름으로 의미를 유지한다.

### 상태 계약과 완료 확인

- 기존 스레드·목록 구독을 상태의 단일 공급원으로 유지한다. 명령 응답은 성공·실패만 전달하며 UI의 스레드 상태를 직접 변경하지 않는다.
- Rust의 스레드, 스레드 패치, 목록용 스레드 정보와 대응 TypeScript 타입에 비영속 `completedTurnId`와 `requestFailure`를 추가한다. 각각 마지막 정상 완료 턴 ID와 현재 요청 실패를 전달한다. 기본값은 없음이다.
- 취소를 제외한 정상적인 프로토콜 응답 종료는 완료로 취급한다. 요청 실패·연결 오류·비정상 중단은 완료로 취급하지 않는다. 사용자 중단 처리 중에 정상 종료 이유가 도착해도 사용자 중단으로 취급한다.
- 완료 턴 ID는 다음 대기 메시지를 자동 실행하기 전에 기록한다. 다음 요청이 바로 실행돼 목록에 준비 상태가 나타나지 않더라도 완료를 놓치지 않는다. 텍스트 없이 정상 종료한 응답도 완료 정보가 생긴다.
- 요청 실패에는 대기 메시지 전송 실패도 포함한다. 요청 실패 표시는 다음 요청의 정상 접수 또는 성공적인 연결 복구 시 해제한다. 사용자가 실패한 스레드를 열었다는 이유만으로 오류를 해제하지 않는다.
- 프런트엔드는 스레드별 확인한 완료 턴 ID를 메모리에 유지한다. 실제 화면이 해당 스레드 페이지이고 그 스레드의 완료 정보가 도착하면 확인 처리한다. 앱 포커스·최신 위치·스크롤 위치는 확인 조건에 포함하지 않는다.
- 설정·에이전트 관리 페이지에서는 선택된 스레드 ID가 남아 있어도 확인 처리하지 않는다. 다른 스레드로 이동했을 때 늦게 도착한 업데이트가 새 스레드를 확인 처리해서는 안 된다.
- 페이지 진입 시 기존 미확인 완료를 확인 처리하며, 페이지가 열린 동안 새 응답이 완료되면 즉시 확인한다. 중복 스냅샷·패치·목록 업데이트가 이미 확인한 완료 원을 되살려서는 안 된다.
- 이전 미확인 완료 후 새 요청이 진행되면 진행 표시를 우선한다. 새 요청이 취소되면 그 취소는 새 완료를 만들지 않으며, 기존 미확인 완료는 확인될 때까지 보존한다.
- 완료·확인 정보는 앱 실행 중에만 유지한다. DB와 로컬 스토리지에 저장하지 않고 재시작 후 과거 응답 이력에서 재구성하지 않는다. DB 스키마 v1과 저장 형식을 변경하지 않는다.
- 완료 확인은 목록 정렬 기준인 마지막 요청 시각을 변경하지 않는다. 스레드 삭제 시 관련 프런트엔드 확인 정보를 제거한다.

### 오류와 복구

- 개별 스레드 구독 실패는 해당 행에서 오류가 진행 표시보다 우선한다. 목록 구독 실패는 마지막 목록을 유지하면서 표시된 행들에 상태를 확인할 수 없다는 경고와 툴팁을 제공한다.
- 정상 구독 스냅샷 수신 후 구독 실패 표시를 해제하고 현재 백엔드 상태로 복원한다. 구독 오류와 실제 요청·에이전트 오류를 구분해, 구독 복구만으로 실제 오류까지 해제하지 않는다.
- 기존 자동 재시도, 수동 재연결, 입력 제한, 오류 알림 동작을 유지한다. 메뉴 접근과 오류 상태 표시는 기존 구독 단일 공급원 결정을 따르며 별도의 상태 추측이나 주기적 생존 확인을 추가하지 않는다.

## Testing Decisions

- 주 검증 경계는 기존 앱 통합 테스트와 Rust ACP 통합 테스트다. 앱 테스트는 기존 Tauri 명령·Channel 대역으로 사용자 동작과 구독 입력에 따른 화면 결과를 검증하고, ACP 테스트는 기존 Rust 에이전트 fixture로 실제 완료·승인·취소·실패가 스레드와 목록 구독에 전달되는지 검증한다. 새 테스트 프레임워크나 별도 상태 주입 API를 추가하지 않는다.
- 좋은 테스트는 상태 입력 후 사용자가 볼 수 있는 표시, 메뉴 접근, 확인 동작 또는 구독 소비자가 받는 정보를 검증한다. 내부 signal 구성, DOM 구현 세부사항, 매 애니메이션 프레임은 검증하지 않는다.
- 기존 앱의 스트리밍·완료, 중단·대기 메시지, 승인 응답, 설정 페이지 이동, 구독 재시도와 메뉴 접근 테스트를 선례로 삼는다. Rust에서는 기존 ACP 취소·승인·대기열·목록 구독 통합 테스트를 확장한다.
- 앱 통합 테스트에서 매 요청의 첫 텍스트 전 아이콘 표시, 첫 텍스트 후 제거, 승인 대기·재개, 중단 완료, 텍스트 없는 종료를 검증한다.
- 다른 스레드 완료 원, 페이지 진입 확인, 열린 페이지의 즉시 확인, 설정 페이지의 미확인 유지, 중복 업데이트, 스레드 전환 후 늦은 업데이트, 삭제 후 정보 제거를 검증한다.
- 대기 메시지 연속 실행 시 진행 표시와 이전 완료 정보 보존, 실패·취소가 새 정상 완료를 만들지 않는 동작, 재시작 시 완료 정보 초기화를 검증한다.
- 요청 실패·연결 오류·개별 구독 실패·목록 구독 실패와 각각의 복구를 검증한다. 오류 우선순위와 구독 복구 후 남아 있는 실제 오류도 포함한다.
- 실제 데스크톱에서 라이트·다크 테마, 고정 크기와 정렬, 첫 텍스트 전환, 마우스·키보드 메뉴, 승인 배지의 긴 제목과 공존, 동작 줄이기 설정을 수동으로 확인한다. 이번 기능을 위해 데스크톱 E2E 자동화 기반을 새로 도입하지 않는다.
- 프런트엔드의 기존 전체 검증과 Rust 테스트·Clippy를 실행한다. 각 구현 단계에 필요한 상태 전이 테스트를 포함하며 별도 테스트 전용 작업으로 미루지 않는다.

## Out of Scope

- 앱 재시작 후 미확인 완료 유지, DB 컬럼·마이그레이션, 확인 상태의 서버 저장.
- 앱 포커스·최신 위치·스크롤을 이용한 읽음 판정, 명시적인 읽음·안읽음 조작, 미확인 개수.
- OS 알림, 소리, Dock 배지, 예상 완료 시간·진행률, 새로운 에이전트 프로토콜.
- 기존 인증·승인·대기열·재연결 정책의 변경, 저장 오류를 위한 별도 사이드바 상태 추가.
- 새 데스크톱 E2E 자동화 도입, README 변경, 임시 조사 자료의 Git 이력 추가.
- 이 명세 작성 단계에서 티켓 생성·기능 구현·커밋 수행.

## Further Notes

- 단일 컨텍스트의 기존 도메인 용어를 사용하며, 화면에서 지속적인 대상을 지칭할 때 세션 대신 스레드를 사용한다.
- 구현 시 현재 작업 트리의 마지막 요청 시각·목록 정렬 관련 미커밋 변경을 기준으로 한다. 기존 변경을 되돌리거나 다른 변경의 소유권을 가져오지 않는다.
- 기능은 응답 진행·승인·중단 표시, 완료·확인 표시, 오류·복구 표시의 세 단계로 나눌 수 있다. 각 단계는 사용자 동작부터 상태 전달과 검증까지 작동하는 결과를 갖는다. 후속 티켓 작성은 별도 요청으로 진행한다.
- 색상·크기·주기는 앞선 구현 계획의 기본값을 사용한다. 기존 디자인 시스템의 인라인 상태 표시처럼 대체되는 메뉴·응답과 같은 위치와 정렬을 유지한다.
