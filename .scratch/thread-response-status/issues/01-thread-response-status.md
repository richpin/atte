# 01: 스레드 응답 상태와 완료 확인 UI

**What to build:** 사용자가 대화와 사이드바에서 첫 응답 대기, 진행, 승인 요청, 중단, 미확인 완료, 오류를 구분할 수 있게 한다. 매 요청의 첫 텍스트 전에는 에이전트 아이콘을 확대·축소하고, 사이드바 메뉴 위치에는 진행 스피너·완료 원·오류 아이콘을 표시한다. 스레드 페이지를 열면 완료를 확인 처리하고, 상태 표시 중에도 기존 메뉴를 사용할 수 있게 한다. 상태 전달부터 화면과 검증까지 하나의 티켓으로 완성한다.

**Blocked by:** None (can start immediately).

상세 동작과 계약은 상위 기능 명세를 따른다. 아래 수용 기준은 해당 명세 전체의 구현 완료 조건이다.

## Acceptance criteria

### 첫 응답 대기와 진행

- [x] 매 요청의 활성 턴에 응답 텍스트가 없고 `running`일 때 사용자 메시지 아래 에이전트 응답의 시작 위치에 기존 에이전트 아이콘을 표시한다. 이미지·폴백·테마 처리를 재사용한다.
- [x] 24px 고정 영역에서 1.4초 주기로 `0.75 → 1 → 0.75` 배율을 반복하며 레이아웃과 메시지 간격을 흔들지 않는다. 첫 텍스트 수신 또는 텍스트 없는 종료 시 대기 아이콘을 제거한다. 후속 요청에서도 동일하게 동작한다.
- [x] 사이드바에서는 연결·스레드 복원·응답 진행·중단 처리 중에 메뉴 위치의 `LoaderCircle`이 1초에 한 바퀴 회전한다. 첫 텍스트 이후 도구 실행 중에도 진행 표시를 유지하고, 연결 중·복원 중·응답 중·중단 중을 상태 이름과 툴팁으로 구분한다.
- [x] 사용자의 중단이 완료되면 스피너를 제거하고 메뉴를 복원한다. 사용자 중단 처리 중에 정상 종료 이유가 도착해도 새 정상 완료로 취급하지 않는다. 비정상 중단은 기존 안내를 유지하고 정상 완료 원을 만들지 않는다.

### 승인 요청과 메뉴 접근

- [x] 승인 대기 시 스피너 대신 파란 배지를 표시한다. 영어는 `Ask for Approval`, 한국어는 `승인 요청`을 사용한다. 마지막 미처리 승인 요청이 해소될 때까지 유지하며, 작업 재개는 명령 성공이 아닌 구독 상태로 판단한다.
- [x] 첫 텍스트 전의 승인 대기에서는 에이전트 아이콘을 정적으로 유지하고, 승인 후 `running`으로 복귀했는데 텍스트가 아직 없으면 확대·축소를 재개한다. 중단 처리·오류·연결 상태에서는 첫 응답 대기 아이콘을 제거한다.
- [x] 스피너·완료 원·오류 아이콘이 메뉴 위치에 있더라도 행의 마우스 호버 또는 키보드 포커스 시 메뉴 버튼으로 바뀐다. 승인 배지는 유지하면서 메뉴 공간을 확보하고, 기존 우클릭 메뉴도 동작한다.

### 완료 전달과 확인

- [x] 스레드, 스레드 패치, 목록용 스레드 정보와 대응 프런트엔드 타입에 비영속 `completedTurnId`와 `requestFailure`를 추가한다. 기존 구독을 상태의 단일 공급원으로 유지하고 명령 응답이나 준비 상태 전환으로 완료를 추측하지 않는다.
- [x] 취소를 제외한 정상 프로토콜 응답 종료는 텍스트가 없어도 완료로 기록한다. 완료 ID는 다음 대기 메시지의 자동 실행 전에 갱신하며, 열지 않은 스레드의 목록 구독에도 전달한다. 요청 실패·연결 오류·비정상 중단은 새 정상 완료를 만들지 않는다.
- [x] 미확인 완료에는 내부가 빈 파란 `Circle`을 표시한다. 확인한 완료 턴 ID는 스레드별 프런트엔드 메모리에 유지하며, 해당 스레드 페이지 진입 또는 열린 페이지에서의 새 완료 수신 시 즉시 확인 처리한다.
- [x] 완료 확인에 앱 포커스·스크롤·최신 위치를 요구하지 않는다. 설정·에이전트 관리 페이지에서는 선택된 스레드 ID만으로 확인 처리하지 않으며, 다른 스레드로 이동한 뒤의 늦은 업데이트가 새 스레드를 확인 처리하지 않는다.
- [x] 중복 스냅샷·패치·목록 업데이트로 확인된 원이 되살아나지 않는다. 다음 요청 진행 중에는 이전 미확인 완료를 숨기되 보존하며, 새 요청이 취소되면 보존된 미확인 완료를 다시 표시한다.
- [x] 완료·확인 정보는 DB나 로컬 스토리지에 저장하지 않고, 재시작 시 초기화하며 과거 응답 이력에서 재구성하지 않는다. 스레드 삭제 시 확인 정보를 정리하고 마지막 요청 시각과 목록 정렬을 변경하지 않는다. DB 스키마 v1과 저장 형식은 변경하지 않는다.

### 오류와 복구

- [x] 일반 요청과 대기 메시지 요청의 실패, 에이전트 연결 오류, 개별 상태 구독 실패를 주황색 `CircleAlert`로 표시한다. 스레드 페이지를 여는 것만으로 실제 오류를 해제하지 않는다.
- [x] 목록 구독 실패 시 마지막 목록을 유지하고 표시된 행들에 상태를 확인할 수 없다는 경고와 툴팁을 제공한다. 정상 구독 수신 시 현재 상태로 복원하되 실제 요청·연결 오류까지 해제하지 않는다.
- [x] 요청 실패 표시는 다음 요청의 정상 접수 또는 성공적인 연결 복구 시 해제한다. 오류 → 승인 요청 → 연결·응답·중단 진행 → 미확인 완료 → 메뉴 순서를 적용하며 가려진 완료·확인 정보는 보존한다.
- [x] 기존 자동 재시도, 수동 재연결, 입력 제한, 오류 알림과 인증·승인·대기열 정책을 유지한다. 별도 상태 추측이나 주기적 생존 확인을 도입하지 않는다.

### 시각·접근성·검증

- [x] 스피너·완료 원·경고 아이콘은 모두 16px, 동일한 선 두께와 정렬을 사용한다. 기존 사이드바의 실행 중·승인 대기·연결 오류 텍스트는 새 표시로 대체한다. 공용 UI와 중앙 스타일 토큰을 재사용한다.
- [x] 파랑은 기본 `#2563EB`·다크 `#3B82F6`, 주황은 기본 `#C2410C`·다크 `#FB923C`를 사용한다. 승인 배지는 같은 파란 계열의 연한 배경과 텍스트로 표시한다. 상태별 접근성 이름과 툴팁을 제공하고 동작 줄이기 설정에서는 회전·확대·축소를 끈다.
- [x] 기존 앱 통합 테스트로 첫 텍스트 전후, 승인·재개·중단, 페이지 진입·설정 이동·늦은 업데이트·삭제, 메뉴 접근, 오류 우선순위와 복구를 검증한다. 내부 signal 구성이나 애니메이션 프레임을 테스트하지 않는다.
- [x] 기존 Rust ACP 통합 테스트와 Rust 에이전트 fixture로 완료·취소·승인·실패의 스레드 및 목록 구독 전달, 대기 메시지 연속 실행 중 완료 보존, 텍스트 없는 완료, 재시작 초기화를 검증한다. 새 테스트 프레임워크·상태 주입 API·데스크톱 E2E 기반을 추가하지 않는다.
- [x] 프런트엔드 전체 검증과 Rust 테스트·Clippy를 실행하고 결과를 기록한다. 실제 데스크톱에서 라이트·다크 테마, 애니메이션·정렬, 긴 제목과 승인 배지, 마우스·키보드·우클릭 메뉴, 동작 줄이기를 수동 확인한다.
- [x] 관련 문서를 최종 동작과 맞추고 기존 미커밋 변경을 보존한다. README와 임시 조사 자료는 변경 범위에 넣지 않는다. 완료 시 아래 Comments에 검증 결과와 완료 사실을 기록한다.
