# 스레드 프로젝트 패널 기반

스레드 페이지 오른쪽에 접이식 패널과 브라우저형 탭을 제공한다. 파일, 인터넷, Git 변경 내역 탐색은 각각 후속 feature에서 구현한다. 이번 단계에서는 빈 새 탭으로 구조를 사용할 수 있다.

## 화면과 상태

- 스레드 헤더의 PanelRight 버튼으로 패널을 열고 접는다. 기존 스레드 정보 카드 토글과 독립적이다. 스레드 페이지에서만 사용할 수 있다.
- 탭 목록, 선택 탭, 펼침 여부와 마지막 너비는 스레드별로 독립적이다. 같은 작업 폴더의 스레드도 공유하지 않는다.
- 처음 진입하는 스레드의 패널은 접혀 있으며 처음 열면 기본 빈 탭 하나를 제공한다. 패널에는 항상 최소 한 개의 탭을 유지한다. 화면 이동과 스레드 전환 때 상태와 탭 콘텐츠를 유지하고 앱 재시작 시 초기화한다. DB와 로컬 스토리지에 저장하지 않는다.
- Corvu 리사이즈 경계를 드래그하거나 키보드로 조절한다. 기본 너비는 360px, 최소 240px, 최대 600px이며 대화 영역에 최소 320px을 확보한다. 접었다 펼치면 마지막 너비를 복원한다.
- 창 크기나 왼쪽 사이드바 변경으로 공간이 부족하면 실제 너비를 제한한다. 560px 미만의 대화·패널 공간에서는 패널을 임시로 숨기고, 공간이 돌아오면 사용자가 요청한 펼침 상태와 너비로 복원한다. 화면 크기 변화는 기억한 너비를 덮어쓰지 않는다.

## 탭

- ＋로 빈 새 탭을 열고 즉시 선택한다. 탭은 오른쪽 끝에 추가한다. 안내 문구는 프로젝트 탐색 용도로만 표시한다.
- 여러 탭을 열어 두되 선택된 하나만 표시한다. 비활성 탭은 콘텐츠를 제거하지 않는다. 접거나 다른 스레드로 이동할 때도 콘텐츠를 제거하지 않는다.
- 각 탭에 닫기 버튼을 제공한다. 선택된 탭을 닫으면 오른쪽 탭, 없으면 왼쪽 탭을 선택한다. 비활성 탭을 닫으면 선택을 유지한다. 마지막 탭을 닫으면 새 기본 빈 탭을 생성하고 선택한다. 패널의 펼침 여부와 너비는 유지한다.
- 닫힌 탭 콘텐츠는 정리한다. 스레드 삭제가 성공하면 해당 스레드의 패널 상태와 모든 콘텐츠를 정리한다.
- Kobalte Tabs의 방향키·Home·End 탐색과 접근성 연결을 사용한다. 탭 닫기 뒤 포커스를 선택된 탭으로 이동한다. 탭이 많으면 가로 스크롤하며 선택된 탭이 보이도록 한다.
- 한국어·영어와 라이트·다크 테마를 지원한다. 탭 드래그 정렬, 고정, 분할 화면과 방문 기록은 포함하지 않는다.

## 후속 feature 연결

`widgets/thread-panel`의 public interface를 앱 계층에서 사용한다. 서로 다른 feature가 widget을 직접 import하지 않도록 앱 계층에서 조합한다. 범용 플러그인 등록 체계는 두지 않는다.

- `createThreadPanelModel()`은 앱 수명의 패널 상태와 최소 한 개 탭 유지를 관리한다. 초기 `openTab`이 실제 콘텐츠를 제공하면 해당 콘텐츠가 첫 탭이 되며 불필요한 기본 빈 탭을 추가하지 않는다. `newTab(threadId)`은 빈 새 탭을 열며 새 패널에서는 기본 탭 하나만 생성한다.
- `openTab(threadId, { id, title, content })`으로 탭을 연다. `id`는 해당 스레드 안에서 고유하다. 동일 ID를 다시 열면 기존 콘텐츠를 유지하고 해당 탭을 선택하며 패널을 펼친다.
- `title`은 문자열 accessor로 제목·언어 변화를 반영한다. `content`는 Solid Component이며 `active`와 `visible` props를 받는다. `active`는 소유 스레드에서 선택된 탭인지, `visible`은 현재 화면에 실제로 표시되는지다. 비활성 스레드의 선택 탭도 `active`는 true일 수 있으므로 백그라운드 작업 제어에는 `visible`을 사용한다.
- `selectTab`, `closeTab`, `setOpen`, `setWidth`로 UI 상태를 변경한다. 없는 탭 선택·닫기는 무시한다. `forget(threadId)`는 스레드 삭제 성공 뒤 호출한다.
- `ThreadPanelLayout`은 대화 영역을 children으로 받고 리사이즈·탭 렌더링·콘텐츠 수명을 관리한다. 구독의 스레드 상태나 ACP와 결합하지 않는다.

## 검증

실제 public interface와 화면을 통해 탭 생성·선택·닫기, 중복 ID 열기, 키보드 탐색, 스레드별 분리, 콘텐츠 유지·정리, 리사이즈·너비 복원·좁은 창을 검증한다. 앱 통합 테스트로 헤더 토글, 화면 이동, 재시작 초기화와 삭제 후 정리를 검증한다. 브라우저에서 드래그 리사이즈와 테마별 배치를 확인하고 `pnpm validate`와 `pnpm build`를 실행한다.

참고: [VS Code Custom Layout](https://code.visualstudio.com/docs/configure/custom-layout)의 보조 사이드바와 탭 패턴을 따른다.
