# 01: 스레드 동기화 책임을 화면에서 분리

**What to build:** 사용자가 스레드를 전환하고 메시지를 보내는 동안, 늦게 도착한 응답이나 중복된 답변 조각이 현재 스레드와 스레드 정보를 잘못 바꾸지 않도록 하는 기존 동작을 유지한다. 이 동기화 규칙을 하나의 스레드 module로 모아 화면은 사용자 입력과 표시를 담당하고, 동기화는 화면 전체를 띄우지 않고 검증할 수 있게 한다.

**Blocked by:** None (can start immediately).

Status: done

## 배경과 범위

현재 스레드 화면은 선택 요청의 순서, 전체 스레드의 revision, 답변 조각의 연속성, 구독 수명, 스레드 정보 목록의 갱신, 비동기 명령 결과의 적용 여부를 함께 관리한다. 화면을 수정할 때 동기화 규칙까지 이해해야 하고, 규칙 검증에도 전체 앱의 화면 설정이 필요하다.

기존 thread slice 안에서 선택된 스레드와 스레드 정보의 동기화를 책임지는 module을 구성한다. 선택·조회, 구독·재구독·정리, 전체 스레드와 답변 조각의 적용, 목록 조회와 구독 결과의 조정, 연결·전송·대기 메시지 삭제·취소·승인 응답 결과의 적용을 함께 다룬다. 화면에는 표시할 상태와 사용자 행동을 위한 작은 interface를 제공한다. 화면 배치, 스크롤, 입력창 표시 등 표현 책임은 화면에 둔다.

기존 통신 adapter와 구독 정리 동작을 활용한다. depth의 기준은 파일 길이가 아니라 화면이 더 이상 응답 순서와 구독 수명 규칙을 직접 조정하지 않는 것이다. 구현자는 현재 코드를 확인해 구체적인 interface를 결정한다. 앞선 설명에서 사용한 함수명과 파일명은 확정 설계가 아니다.

## Acceptance criteria

- [x] 화면이 선택 요청의 순서, revision 비교, 답변 조각의 연속성, 구독 정리를 직접 조정하지 않고 스레드 module의 interface를 사용한다. 기존 slice 구성과 Solid의 반응성·정리 수명을 따른다.
- [x] A 스레드 조회 후 B 스레드를 선택했을 때 A의 늦은 조회 결과가 B를 대체하지 않는다. 이전 스레드의 연결·전송·삭제·취소·승인 응답 또는 실패가 현재 스레드의 표시 상태를 덮어쓰지 않는다.
- [x] 전체 스레드 갱신은 대상과 revision을 확인한다. 답변 조각은 대상 스레드와 현재 작업을 확인하며 중복을 한 번만 반영한다. 순서 누락이나 작업 불일치 시 기존 오류 표시와 재구독 동작을 유지한다.
- [x] 스레드 정보의 초기 조회, 목록 구독, 선택된 스레드 갱신이 경합해도 기존 갱신 규칙을 보존하며, 오래된 조회 결과로 최신 목록을 되돌리지 않는다.
- [x] 스레드 전환과 화면 정리 시 구독을 정리한다. 구독 등록이 뒤늦게 완료된 경우에도 정리하며, 이전 구독의 정리 실패가 새 스레드의 전송을 막지 않는다. 구독 해제가 백엔드의 스레드 실행을 중단하지 않는다.
- [x] 기존 스레드 생성·재개·전송·취소·승인 요청·대기 메시지 삭제 흐름과 입력창의 유지·초기화 동작을 보존한다. 화면 모양과 스크롤 동작도 유지한다.
- [x] 화면과 같은 interface를 사용하는 테스트로 선택 경합, 오래된 전체 스레드, 중복·잘못된 답변 조각, 목록 조회 경합, 늦은 구독 등록·정리를 검증한다. 기존 테스트를 활용하거나 옮기고 핵심 화면 연결 테스트를 유지한다.
- [x] 관련 프런트엔드 테스트, 타입 검사, 포맷·정적 검사와 FSD 검사를 통과한다. 변경된 설계를 설명하는 기존 문서가 있으면 함께 갱신하고 검증 결과를 Comments에 기록한다.

## 범위 밖

백엔드 스레드 상태 변경 리팩터링, Tauri 명령·이벤트 형식 변경, 데이터베이스 변경, 새 사용자 기능은 포함하지 않는다. 범용 상태 프레임워크나 별도 adapter 체계를 추가하지 않는다.
