# Open working folder

스레드 헤더의 오른쪽 메뉴에서 Reconnect 바로 아래에 다음으로 열기(Open in) 서브메뉴를 제공한다. 현재 스레드의 작업 폴더 자체를 선택한 앱으로 열며 에이전트 연결 상태와 무관하게 동작한다. macOS에서만 표시한다.

## Native discovery

지원 앱 이름·bundle ID 목록을 코드에 유지하지 않는다. NSWorkspace.URLsForApplicationsToOpenURL로 해당 컴퓨터에서 열 대상을 처리할 수 있는 앱을 조회하고 OS가 반환하는 적합도 순서를 유지한다. 앱 이름은 OS의 현지화된 표시 이름을 사용한다. 목록에는 OS에 해당 형식을 처리한다고 등록된 앱이 표시되므로 코딩 에디터 이외의 앱도 포함될 수 있다.

조회 대상은 스레드에 저장된 작업 폴더 하나다. 폴더 내부의 파일을 탐색하거나 프로젝트 형식을 판별하지 않는다. 프로젝트별 앱 추가, 우선순위, 목록 병합, 파일명 표시는 제공하지 않는다. Finder를 포함해 앱 목록과 순서는 OS 결과를 그대로 따른다.

## UI

메뉴를 열거나 선택 스레드가 바뀔 때 앱과 아이콘을 다시 조회한다. 이전 스레드의 비동기 조회 결과를 새 스레드에 표시하지 않는다. 조회 중에는 로딩, 실패하면 메뉴를 유지하는 재시도 항목, 결과가 없으면 비활성 안내 항목을 표시한다.

각 항목 왼쪽에 설치된 앱의 실제 아이콘을 표시한다. NSWorkspace에서 추출한 32×32 PNG를 16px로 표시하며 라이트·다크 테마에서 원래 색상을 유지한다. 아이콘 추출이나 이미지 로딩 실패 시 일반 앱 아이콘을 표시한다. 앱 이름을 접근성 레이블로 사용하며 아이콘은 장식 요소다.

프런트엔드 기능은 features/open-working-folder에 위치한다. 기존 Kobalte 메뉴와 Image를 사용하고 서브메뉴는 Portal로 렌더링한다. 메뉴 이동과 선택은 Kobalte의 키보드 동작을 유지한다.

목록 맨 아래에 구분선 없이 ‘다른 앱…’ 항목을 제공한다. 자동 조회 중이거나 조회 실패·빈 목록인 경우에도 이 항목을 사용할 수 있다. 선택하면 /Applications에서 시작하는 macOS 네이티브 앱 선택 창을 열며 다른 위치로 이동할 수 있고 .app 번들 하나를 선택할 수 있다. 취소하면 아무 작업도 하지 않는다. 직접 선택한 앱으로는 현재 작업 폴더 자체를 열고 앱 목록·기본 앱·프로젝트 탐색 규칙을 저장하거나 변경하지 않는다.

## Commands

list_working_folder_apps는 threadId를 받아 { id, name, icon } 목록을 반환한다. icon은 PNG data URL 또는 null이고 id는 OS가 반환한 앱을 식별하는 불투명 문자열이다. open_working_folder는 threadId와 이 id를 target으로 받는다.

Rust가 스레드의 작업 폴더를 조회하고 실행 직전에 작업 폴더의 OS 앱 목록을 다시 확인한다. 현재 조회 결과에 없는 임의 앱은 거부하며 프런트엔드의 경로 문자열을 실행 권한으로 신뢰하지 않는다. 앱 실행은 블로킹 작업으로 분리하고 AppKit 작업은 메인 스레드에서 수행한다. OS 실행 중 스레드 상태 잠금을 유지하지 않는다. 폴더 없음, 앱 연결 없음, 스레드 없음, 조회 실패, 실행 실패를 구분하고 한국어·영어 메시지를 제공한다.

open_working_folder_with_app_picker는 threadId와 현지화된 dialogTitle만 받는다. 앱 경로는 Rust의 네이티브 선택 창에서만 얻으며 프런트엔드에서는 받지 않는다. 선택된 번들이 실행 파일을 가진 APPL 형식의 .app인지 확인한다. 선택 창을 여는 시점의 스레드 ID를 유지하고 선택 후 같은 스레드의 작업 폴더를 다시 확인한다. 수동 선택은 OS의 폴더 연결 목록에 없는 앱도 허용한다.

DB와 CSP는 변경하지 않는다. 수동 앱 등록, 기본 앱 변경, 프로젝트 파일 탐색은 포함하지 않는다.
