# 01: 입력창을 유지하는 컴팩트 Sign-in Dialog

**What to build:** 에이전트 인증이 필요해도 메시지 입력창과 작성 중인 메시지·첨부를 유지한다. 사용자는 입력창 하단의 `Sign in` 동작으로 작은 Dialog를 열어 지원되는 인증 방법을 선택하고, 인증 진행·취소·오류·재시도를 같은 창에서 처리한다. 인증 후 시작 스레드의 재연결이 성공하면 입력창으로 돌아오며, 작성한 메시지는 직접 전송한다. 기존 인증 API와 에이전트별 상태 모델, 공통 Dialog를 재사용해 UI부터 App 통합 테스트까지 한 작업에서 완성한다.

**Blocked by:** None (can start immediately).

- [x] 인증이 필요한 상태에서도 기존 메시지 입력창이 유지되고 메시지를 편집할 수 있다. 작성 중인 메시지와 첨부는 Dialog 열기·닫기·취소·실패·완료 과정에서 보존된다.
- [x] 인증 및 스레드 연결 준비가 완료되기 전에는 전송 버튼과 제출 처리 양쪽에서 메시지 전송을 차단한다. 첨부 추가와 에이전트 설정 변경은 기존 가용성 규칙을 유지한다.
- [x] 입력창 하단에 인증 필요 안내와 Sign-in 진입 동작을 제공한다. Dialog는 사용자의 명시적인 동작으로 열리며 인증 필요 상태나 화면 재진입만으로 자동으로 열리지 않는다.
- [x] 공통 Dialog의 접근성과 닫기 동작을 재사용한다. 로그인 전용 UI는 에이전트 인증 feature에 두고, 스레드 페이지는 열림 상태 및 스레드 연결 흐름을 조정한다. 공통 UI에 로그인 전용 상태를 넣지 않는다.
- [x] Dialog는 최대 폭 420px과 기본 내부 여백 24px을 사용한다. 선택 행은 약 64–68px 높이와 8px 간격으로 배치하고 이름과 설명을 왼쪽 정렬한다. 얇은 테두리와 약한 hover 배경을 사용하며 모든 방법의 강조 수준을 동일하게 유지한다.
- [x] Dialog 제목은 현재 에이전트를 식별한다. 기존 조회 결과에서 지원되는 인증 방법만 제공 순서대로 표시하고, 에이전트가 제공한 이름과 설명을 사용한다. Claude의 두 방법을 고정하지 않으며 과금 정책을 추정하지 않는다.
- [x] 이름과 설명을 포함한 행 전체가 하나의 키보드 접근 가능한 버튼이다. 선택하면 별도 Continue 단계 없이 해당 인증을 시작한다. 방법이 하나여도 자동으로 시작하지 않는다.
- [x] 조회 중 상태, 지원되는 방법 없음, 조회·로그인 오류와 재시도를 Dialog 안에서 명확히 표시한다. 같은 실패를 중복 알리지 않는다.
- [x] 브라우저 및 터미널 안내는 해당 인증 방법에 맞게 표시한다. 인증 중 선택한 방법과 진행 상태를 보여주고 중복 시작을 막는다.
- [x] 명시적인 인증 취소는 기존 취소 API를 호출한다. 취소가 처리되는 동안 새 인증을 시작할 수 없고, 처리 후 방법을 다시 선택할 수 있다. 취소 후 늦게 도착한 완료 결과는 무시한다.
- [x] 닫기 버튼, Escape 및 외부 클릭으로 Dialog를 닫으면 진행 중인 인증도 같은 취소 경로로 중단한다. 다시 Sign-in을 눌러 열 수 있다.
- [x] 다른 스레드나 페이지로 이동하면 이전 화면의 Dialog를 표시하지 않고 이전 화면으로 포커스를 복원하지 않는다. 이동 자체로 에이전트별 인증을 취소하지 않으며, 같은 에이전트의 스레드에서 Sign-in을 다시 열면 기존 진행 상태를 표시한다.
- [x] 인증 후 현재 선택된 시작 스레드를 기존 규칙에 따라 한 번 재연결한다. 다른 스레드를 자동으로 재연결하지 않으며, 이동했다가 시작 스레드로 돌아왔을 때 재연결하는 기존 동작을 유지한다.
- [x] 인증 완료 후 재연결 진행을 표시하고, 스레드 구독이 재연결 성공을 전달한 뒤 Dialog를 닫는다. 인증 결과나 명령 응답으로 스레드 상태를 직접 덮어쓰지 않는다.
- [x] 재연결 실패 시 입력 내용을 보존하고 기존 복구 동작으로 이어진다. 이미 성공한 로그인을 로그인 실패로 취급하지 않는다.
- [x] 일반적인 닫기·취소 시 Sign-in 진입 버튼으로, 인증 및 재연결 성공 시 메시지 입력창으로 포커스를 돌린다. 인증이나 재연결 성공으로 메시지를 자동 전송하거나 입력을 비우지 않는다.
- [x] 한국어·영어 안내와 접근성 이름을 기존 i18n 체계로 제공한다. 두 테마 및 좁은 창에서 화면 가장자리 여백을 확보하고 긴 이름·설명이 잘리거나 겹치지 않게 줄바꿈한다.
- [x] 기존 App 통합 테스트를 중심으로 진입·선택·닫기·취소·오류·재시도·빈 목록·전송 차단·메시지 및 첨부 보존·재연결·포커스 복원을 검증한다. 실제 인증 서비스 대신 기존 명령 mock과 제어 가능한 비동기 결과를 사용한다.
- [x] 기존 인증 회귀 테스트를 Dialog 진입 흐름에 맞게 갱신하면서 지원되지 않는 방법 제외, 인증 공유, 중복 시작 방지, 취소 후 늦은 결과 무시, 스레드 이동 및 다른 스레드 재연결 방지 보장을 유지한다. 별도 Dialog 컴포넌트 테스트 경계를 추가하지 않는다.
- [x] 밝은 테마·어두운 테마·좁은 창·긴 인증 문구를 실제 화면에서 확인한다. 내부 signal, DOM 깊이, Tailwind 클래스를 단언하는 테스트는 만들지 않는다.
- [x] 백엔드 API, 데이터베이스 스키마, 인증 프로토콜 및 자격 증명 저장 방식은 변경하지 않는다. 새 UI 라이브러리 도입, 공통 Dialog 전체 개편, 에이전트 관리 화면 개편 및 README 변경은 포함하지 않는다.
