# 입력창을 유지하는 컴팩트 Sign-in Dialog

## Problem Statement

Atte에서 에이전트 인증이 필요하면 메시지 입력창 전체가 로그인 선택 영역으로 바뀐다. 긴 강조 버튼과 버튼 밖의 설명이 넓은 입력 영역을 채워 로그인 선택 단계가 지나치게 크고, 메시지를 작성하는 화면의 연속성이 끊긴다. 사용자는 작성 중인 메시지와 첨부를 유지하면서 작은 영역에서 로그인 방법을 선택하고 작업을 이어가고 싶다.

## Solution

기존 메시지 입력창을 유지하고, 인증이 필요한 상태에서는 입력창 하단에 짧은 안내와 `Sign in` 동작을 제공한다. 사용자가 이를 누르면 공통 Dialog를 사용하는 최대 폭 420px의 로그인 창을 연다. 로그인 창은 사용자가 선택한 첫 번째 시안인 컴팩트 선택 목록을 따른다.

각 로그인 방법은 이름과 설명을 함께 담은 왼쪽 정렬 행으로 표시하고, 행 전체를 누르면 해당 인증을 시작한다. 두 방법 모두 중립적인 테두리와 같은 시각적 강도로 표시한다. 인증 진행과 오류도 같은 Dialog에서 처리한다. 인증 후 현재 스레드의 재연결이 성공하면 Dialog를 닫고 메시지 입력창으로 돌아간다. 작성 중인 메시지와 첨부는 유지하며 자동 전송하지 않는다.

## User Stories

1. As an Atte 사용자, I want 인증이 필요해도 기존 메시지 입력창을 계속 볼 수 있기를, so that 작업 맥락이 유지된다.
2. As an Atte 사용자, I want 인증 전에도 메시지를 작성하고 수정할 수 있기를, so that 로그인 여부와 관계없이 생각을 정리할 수 있다.
3. As an Atte 사용자, I want 작성 중인 메시지가 로그인 창을 열고 닫아도 유지되기를, so that 다시 입력할 필요가 없다.
4. As an Atte 사용자, I want 이미 선택한 첨부가 인증 과정에서도 유지되기를, so that 자료를 다시 선택할 필요가 없다.
5. As an Atte 사용자, I want 인증이 필요한 이유와 Sign-in 동작을 입력창에서 확인하기를, so that 전송할 수 없는 이유와 다음 행동을 알 수 있다.
6. As an Atte 사용자, I want 인증 전에는 메시지 전송이 차단되기를, so that 실행할 수 없는 요청을 보내지 않는다.
7. As an Atte 사용자, I want 로그인 창을 명시적으로 열기를, so that 화면 진입 때마다 작업이 자동으로 가로막히지 않는다.
8. As an Atte 사용자, I want 좁고 중앙에 배치된 로그인 창에서 인증 방법을 비교하기를, so that 불필요하게 넓은 화면을 읽지 않아도 된다.
9. As an Atte 사용자, I want 로그인 방법의 이름과 설명을 같은 행에서 읽기를, so that 각 선택지의 의미를 쉽게 이해한다.
10. As a Claude 사용자, I want 구독을 사용하는 방법과 API 사용량에 따라 과금되는 방법을 구분하기를, so that 내 계정에 맞는 방법을 선택한다.
11. As an Atte 사용자, I want 각 인증 방법이 동등한 시각적 강도로 표시되기를, so that 과금 방법을 불필요한 유도 없이 선택한다.
12. As an Atte 사용자, I want 설명을 포함한 선택 행 전체를 누르기를, so that 작은 버튼을 정확히 겨냥할 필요가 없다.
13. As an Atte 사용자, I want 방법을 선택하면 별도 Continue 단계 없이 인증이 시작되기를, so that 불필요한 클릭이 없다.
14. As an Atte 사용자, I want 선택한 에이전트가 지원하는 인증 방법만 표시되기를, so that 사용할 수 없는 방법을 선택하지 않는다.
15. As an Atte 사용자, I want 로그인 방법을 조회하는 동안 진행 상태를 확인하기를, so that 화면이 멈춘 것으로 오해하지 않는다.
16. As an Atte 사용자, I want 브라우저 또는 터미널로 인증이 이어지는 것을 해당 방법에 맞게 안내받기를, so that 어디에서 인증을 완료해야 하는지 안다.
17. As an Atte 사용자, I want 인증 중 선택한 방법과 진행 상태를 확인하기를, so that 현재 진행 상황을 이해한다.
18. As an Atte 사용자, I want 인증 중 다른 로그인 요청이 중복으로 시작되지 않기를, so that 인증 흐름이 충돌하지 않는다.
19. As an Atte 사용자, I want 인증을 취소하고 다시 방법을 선택하기를, so that 잘못 선택한 방법을 바꿀 수 있다.
20. As an Atte 사용자, I want 로그인 창을 닫을 수 있기를, so that 인증을 중단하고 메시지 작성으로 돌아갈 수 있다.
21. As an Atte 사용자, I want 로그인 실패 이유와 재시도 동작을 확인하기를, so that 문제를 이해하고 다시 시도한다.
22. As an Atte 사용자, I want 로그인 방법이 없을 때 명확한 안내를 받기를, so that 빈 창에서 기다리지 않는다.
23. As an Atte 사용자, I want 인증 완료 후 현재 스레드가 재연결되기를, so that 별도의 중복 연결 없이 작업을 이어간다.
24. As an Atte 사용자, I want 재연결 실패 시 입력 내용을 보존하고 복구 동작을 확인하기를, so that 작성 내용을 잃지 않고 대응한다.
25. As an Atte 사용자, I want 인증 성공이 작성한 메시지를 자동 전송하지 않기를, so that 내용을 검토한 뒤 직접 전송한다.
26. As an Atte 사용자, I want Dialog를 닫거나 인증을 완료했을 때 적절한 입력 위치로 포커스가 돌아가기를, so that 키보드로 작업을 이어간다.
27. As an Atte 사용자, I want 다른 스레드에서 완료된 인증이 현재 스레드에 잘못된 재연결이나 전송을 일으키지 않기를, so that 스레드 사이의 작업이 섞이지 않는다.
28. As an Atte 사용자, I want 밝은 테마, 어두운 테마, 좁은 창에서도 선택지와 설명을 읽을 수 있기를, so that 환경에 관계없이 로그인할 수 있다.

## Implementation Decisions

- 공통 Dialog의 접근성, Portal, 포커스 관리, 닫기 동작을 재사용한다. 로그인 전용 상태나 문구는 공통 UI 모듈에 넣지 않는다.
- 로그인 선택, 로딩, 인증 진행, 오류를 표시하는 SignInDialog를 에이전트 인증 feature에 둔다. 스레드 페이지는 Dialog의 열림 상태와 현재 스레드에 대한 연결 흐름을 조정한다. 입력창은 안내와 진입 동작을 표시한다.
- Dialog 열림 상태는 로컬 UI 상태이며 에이전트의 인증 상태와 구분한다. 인증 필요 상태를 그대로 열림 상태에 연결하지 않아 사용자가 닫은 창이 자동으로 다시 열리지 않게 한다.
- 인증이 필요한 상태에서 입력창을 다른 UI로 교체하는 분기를 제거한다. 입력창과 작성 내용은 유지한다. 메시지 편집을 허용하며, 인증과 연결 준비가 완료되기 전 전송은 버튼과 제출 처리 양쪽에서 차단한다.
- 첨부 보존은 기존 입력창의 로컬 상태를 사용한다. 인증 때문에 첨부를 삭제하거나 작성 내용을 초기화하지 않는다. 첨부 추가와 에이전트 설정 변경은 기존 기능별 가용성 규칙을 유지한다.
- Dialog는 최대 폭 420px, 기본 내부 여백 24px을 사용하며 좁은 창에서는 화면 가장자리 여백을 확보한다. 선택 행은 약 64–68px 높이, 8px 간격, 얇은 테두리, 약한 hover 배경을 사용한다. 이름은 약 14px, 설명은 12–13px로 표시하며 긴 내용은 잘라내지 않고 줄바꿈한다.
- 선택 행은 실제 버튼으로 구현하고 이름과 설명을 함께 포함한다. 모든 방법의 강조 수준을 동일하게 유지한다. 공통 디자인 토큰과 기존 UI 규칙에 맞춰 두 테마를 지원한다.
- Dialog 제목은 현재 에이전트를 식별한다. Claude의 두 선택지를 고정 목록으로 넣지 않고 기존 인증 조회 결과의 지원되는 방법을 순서대로 표시한다. 방법이 하나여도 바로 인증을 시작하지 않고 명시적인 선택을 받는다.
- 에이전트가 제공한 이름과 설명을 우선 사용한다. 화면 예시의 Claude 구독 및 Console 문구는 디자인 설명이며, 에이전트별 이름이나 과금 정책을 프런트엔드에서 추정하지 않는다.
- 브라우저 안내는 브라우저 인증에 맞게, 터미널 안내는 터미널 인증에 맞게 제공한다. 모든 에이전트가 브라우저에서 로그인한다고 일괄 안내하지 않는다.
- 로딩, 인증 진행, 오류, 지원되는 방법이 없는 상태를 Dialog 안에서 처리한다. 오류에는 재시도 동작을 제공하며 기존 인증 조회·로그인·취소 API를 재사용한다. 같은 실패를 중복 알리지 않는다.
- 인증 진행 중에는 중복 시작을 막고 취소 동작을 제공한다. 닫기 버튼, Escape, 외부 클릭으로 Dialog를 닫으면 진행 중인 인증도 기존 취소 경로로 중단한다. 취소가 처리되는 동안 새 인증을 시작할 수 없으며 늦게 도착한 완료 결과는 무시한다.
- 다른 스레드나 페이지로 이동하면 이전 화면의 Dialog는 표시하지 않는다. 화면 이동 자체로 에이전트별 인증을 취소하지 않으며, 같은 에이전트의 스레드에서 다시 Sign-in을 열면 기존 인증 진행 상태를 표시한다. 인증 상태를 에이전트별로 공유하는 기존 모델과 취소 결과의 generation 검증은 유지한다.
- 인증 후 현재 선택된 시작 스레드만 기존 규칙에 따라 한 번 재연결한다. 다른 스레드를 자동으로 재연결하지 않는다. 인증 결과와 명령 응답으로 스레드 상태를 직접 덮어쓰지 않고 스레드 구독을 단일 공급원으로 유지한다.
- 인증 완료 후 재연결 중에는 상태를 표시한다. 재연결 성공은 현재 스레드의 구독 상태로 확인한 뒤 Dialog를 닫는다. 재연결 실패는 기존 복구 동작으로 이어지며 로그인 성공을 실패한 로그인처럼 다시 처리하지 않는다.
- 인증 및 재연결 성공 후에는 메시지 입력창으로 포커스를 돌린다. 일반적인 닫기 또는 취소 시에는 Sign-in 진입 버튼으로 포커스를 복원한다. 스레드나 페이지 이동 후에는 이전 화면으로 포커스를 되돌리지 않는다.
- 입력 내용은 인증이나 재연결 성공만으로 비우거나 전송하지 않는다. 기존처럼 실제 전송 명령이 성공했을 때만 입력을 비운다.
- 한국어·영어 안내와 접근성 이름을 기존 i18n 체계로 제공한다. 백엔드 API 및 데이터베이스 스키마 변경은 필요하지 않다.

## Testing Decisions

- 기존 App 통합 테스트를 주된 테스트 경계 하나로 사용한다. 실제 앱을 렌더링하고 사용자 조작, 접근성 역할, 표시되는 상태, 기존 Tauri 명령 경계를 통해 결과를 검증한다.
- 좋은 테스트는 사용자가 관찰할 수 있는 동작을 검증한다. 내부 signal, 컴포넌트 분할, Tailwind 클래스, 특정 DOM 깊이를 단언하지 않는다.
- 기존 App 인증 테스트에 로그인 방법 조회, 지원되지 않는 방법 제외, 에이전트별 인증 진행 공유, 취소 후 늦은 완료 무시, 다른 스레드 재연결 방지, 입력을 전송하지 않는 재연결 사례가 있다. 이 선행 테스트를 새 Dialog 진입 흐름에 맞게 갱신하고 회귀 보장 내용을 유지한다.
- 인증 필요 상태에서도 입력창이 존재하고 편집 가능하지만 전송 명령은 발생하지 않는지 검증한다. Dialog가 자동으로 열리지 않고 Sign-in 동작으로 열리는지 검증한다.
- 이름과 설명이 같은 선택 동작에 포함되는지, 지원되는 방법만 표시되는지, 방법 하나 및 방법 없음 상태가 명확한지 검증한다.
- 로딩·진행·오류·재시도, 중복 시작 방지, 명시적 취소 및 Dialog 닫기에 따른 취소를 검증한다.
- Dialog 열기·닫기·취소·실패·완료 과정에서 메시지와 첨부가 유지되고 자동 전송되지 않는지 검증한다.
- 인증 후 시작 스레드의 구독 기반 재연결, 재연결 실패, 스레드 이동 중 진행 상태 공유, 다른 스레드의 자동 재연결 방지 및 취소 후 오래된 완료 결과 무시를 검증한다. 시작 스레드로 돌아왔을 때 재연결하는 기존 동작도 유지한다.
- 키보드로 열기, 선택, Escape 닫기를 검증하고 닫기 후 진입 버튼 또는 성공 후 입력창으로 포커스가 돌아가는지 검증한다. 공통 Dialog 라이브러리의 모든 내부 동작을 별도로 재시험하지 않는다.
- 밝은 테마와 어두운 테마, 좁은 창, 긴 인증 방법 이름 및 설명의 줄바꿈은 실제 화면에서 시각적으로 확인한다. 실서비스 인증은 자동 테스트에서 실행하지 않고 기존 명령 mock과 제어 가능한 비동기 결과를 활용한다.
- 사용자는 기존 App 통합 테스트 중심의 경계에 동의했다. 별도 Dialog 컴포넌트 테스트 경계를 새로 추가하지 않는다.

## Out of Scope

- 실제 기능 구현 및 작업 티켓 분할은 이 명세 작성 요청의 범위 밖이다.
- 인증 프로토콜, 자격 증명 저장, OAuth 또는 터미널 인증 방식의 변경.
- 새로운 로그인 방법, 계정 전환, 결제·구독 관리, API key 직접 입력 UI.

## Further Notes

- 사용자는 두 시안 중 컴팩트 선택 목록을 선택했고, 공통 Dialog로 Sign-in을 표시하면서 기존 입력창을 유지하는 구성을 제안했다.
- Linear와 Notion의 좁은 로그인 영역과 인증 선택 패턴, Claude Code의 인증 방법 구분을 참고했다. 시각적 우선순위는 특정 과금 방법으로 유도하지 않는 중립적인 선택 목록으로 결정했다.
- 메시지 입력창은 로컬 UI 상태이고 스레드 상태는 구독을 단일 공급원으로 사용한다는 기존 ADR을 따른다.
- 명시적 Dialog 닫기에 따른 인증 취소, 지원되는 방법 없음 상태, 재연결 진행 표시 등은 합의한 구성을 구현 가능한 동작으로 구체화한 결정이다. 화면 이동 시 에이전트별 인증 공유와 시작 스레드의 재연결 규칙은 기존 동작을 유지한다.
- Status는 명세가 구현 착수 가능한 상태임을 나타내며, 구현 완료 또는 자동 구현 요청을 의미하지 않는다.
