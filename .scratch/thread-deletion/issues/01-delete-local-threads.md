# 01: 로컬 스레드 삭제를 끝까지 제공

**What to build:** ACP 세션이 아직 없는 로컬 스레드를 사이드바 메뉴와 확인 창을 통해 삭제할 수 있게 한다. 삭제는 로컬 저장소, 대기 메시지, 인메모리 목록과 현재 화면까지 하나의 사용자 동작으로 정리하며, 로컬 실패만 사용자가 재시도할 수 있게 표시한다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 스레드 행 우클릭과 행의 hover/focus 시 오른쪽 끝에 나타나는 세로 말줄임표 버튼이 동일한 메뉴를 연다.
- [x] 행 선택 button과 메뉴 trigger가 중첩되지 않으며, 메뉴 trigger와 항목은 키보드 및 보조 기술로 사용할 수 있다.
- [x] 메뉴의 위험 스타일 `삭제` 항목이 제목 `스레드를 삭제할까요?`, 설명 `이 스레드가 영구적으로 삭제됩니다. 이 작업은 취소할 수 없습니다.`인 확인 창을 연다.
- [x] `취소`는 command를 호출하지 않고 메뉴와 확인 창을 닫으며 현재 선택과 작성 중 입력을 유지한다.
- [x] `삭제`를 누르면 중복 제출을 막고 로컬 삭제 결과가 반환될 때까지 확인 창을 유지한다.
- [x] 삭제 command는 대상 스레드와 그 대기 메시지를 로컬 저장소에서 제거한다.
- [x] 로컬 삭제가 성공하면 대상이 인메모리 목록과 목록 구독 결과에서 사라지고 앱 재시작 후에도 복원되지 않는다.
- [x] ACP 세션 ID가 없는 로컬 초안 삭제는 에이전트 프로세스나 ACP 연결을 시작하지 않는다.
- [x] 현재 선택된 스레드 삭제가 성공하면 해당 view와 구독을 정리하고 다른 스레드를 자동 선택하지 않은 빈 시작 화면을 표시한다.
- [x] 선택되지 않은 스레드 삭제가 성공하면 현재 선택된 스레드와 작성 중 입력을 유지한다.
- [x] 성공 시 확인 창을 닫고 success toast를 표시하지 않는다.
- [x] 로컬 저장소 삭제가 실패하면 스레드와 목록을 유지하고 확인 창 안의 접근 가능한 오류를 표시하며 재시도를 허용한다.
- [x] 삭제와 겹친 늦은 open, connect, send, subscription 등록 또는 목록 update가 삭제된 스레드를 다시 선택하거나 목록에 추가하지 않는다.
- [x] 공개 Threads API와 실제 SQLite test store를 사용하는 통합 테스트가 영속 삭제, 목록 발행, 대기 메시지 제거와 로컬 실패 계약을 검증한다.
- [x] 렌더링된 앱과 mock Tauri command 테스트가 메뉴 진입, 확인·취소, 선택/비선택 삭제, 빈 화면과 오류 UI를 사용자 동작으로 검증한다.
