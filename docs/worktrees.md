# Worktree에서 새 스레드 시작

새 스레드는 기본적으로 선택한 기존 폴더에서 시작한다. 작업 폴더와 에이전트 아래의 `새 worktree` 스위치를 켜면 선택한 폴더의 현재 HEAD 커밋을 새 detached HEAD checkout으로 준비한다. 일반 폴더, bare 저장소, 커밋 없는 저장소에서는 이 옵션을 사용할 수 없다. 시스템 Git이 필요하다. 세 행은 구분선을 포함해 각각 54px 높이를 사용한다. 스위치는 18px 높이이며 입력 열의 왼쪽에 정렬한다. 별도 설명 문구는 표시하지 않는다.

생성 위치는 `~/.atte/worktrees/<스레드 UUID>/<저장소 이름>/`이다. 저장소 전체를 checkout하며 하위 폴더를 선택했다면 새 checkout 안의 같은 상대 경로에서 에이전트를 실행한다. 선택한 하위 폴더가 해당 커밋에 없거나 심볼릭 링크를 따라 checkout 밖으로 나가면 생성하지 않는다. 재연결 시에도 실제 작업 폴더가 checkout 내부에 있는지 확인한다. 기존 linked worktree를 원본으로 선택할 수도 있다.

미커밋 변경, 미추적 파일, 의존성 설치와 로컬 환경 파일 복사, 서브모듈 자동 초기화는 제공하지 않는다. 프런트엔드의 저장소 조회는 안내용이며 생성 시 백엔드가 HEAD와 조건을 다시 확인한다. 실제 생성 시 확인한 커밋을 사용한다.

`workingFolder`는 실제 실행·파일 패널·외부 편집기에서 사용하는 폴더다. `worktree` 메타데이터의 `sourceFolder`는 원본 폴더, `root`는 생성한 checkout 루트다. 이 정보는 SQLite v1에 저장하고 목록과 스레드 구독에도 전달한다. 사이드바는 원본 폴더로 그룹화하며 worktree 스레드 우측 끝에는 Split 아이콘을 시계 방향으로 90도 회전해 표시한다. 호버·키보드 포커스·메뉴 열림 중에는 메뉴 버튼으로 교체한다. 기존 상태 표시와 승인 배지는 유지한다. 헤더에는 ID를 추가하지 않는다.

worktree 생성과 스레드 저장이 끝난 뒤 에이전트를 연결한다. 저장 전 실패하면 이번 생성의 checkout만 Git의 일반 remove로 정리하고, 정리에 실패하면 경로를 안내한다. 저장 후 연결 실패는 기존 재연결 흐름을 사용한다. 앱 종료와 생성 도중 종료되어 남은 디렉터리는 자동 정리하지 않는다.

## 스레드 삭제

worktree 스레드의 삭제 확인 Dialog는 기존 안내 아래 Callout에 worktree 폴더 경로와 미커밋 변경·미추적 파일을 포함한 전체 작업 파일 삭제를 명시한다. 기존 폴더를 사용하는 스레드에는 이 Callout을 표시하지 않으며 폴더도 삭제하지 않는다.

확인 후에는 해당 worktree의 에이전트 프로세스를 종료하고 회수한 다음 Git CLI의 `worktree remove --force`로 checkout을 제거한다. 상위 스레드 UUID 폴더에서는 Finder의 `.DS_Store`를 정리하고 비어 있을 때 폴더도 제거한다. 이 부가 정리는 삭제 성공 여부에 영향을 주지 않으며, 다른 파일이 있으면 폴더와 함께 보존한다. 잠긴 worktree는 강제로 잠금을 해제하지 않는다. 생성 실패 되돌리기는 계속 일반 remove를 사용한다. Git 작업 중 스레드 전역 잠금을 유지하지 않으며 삭제 중인 worktree 내부에서는 소유 스레드와 같은 폴더를 사용하는 다른 스레드 모두 새 연결·입력·스레드 생성을 받지 않는다. 해당 폴더의 연결은 함께 중단하며 다른 스레드 기록은 유지한다.

프로세스 종료나 worktree 제거가 실패하면 스레드를 보존하고 오류를 표시해 다시 시도할 수 있게 한다. 외부에서 이미 삭제·정리한 worktree는 제거된 것으로 처리한다. worktree 제거 후 DB 삭제가 실패하면 스레드 기록은 남지만 작업 폴더는 이미 제거된 상태이며 삭제를 재시도할 수 있다. 스레드 삭제 성공은 checkout 제거와 DB 기록 삭제가 모두 끝났음을 뜻한다. Git 객체와 사용자가 만든 브랜치는 공유 저장소에 남으며 커밋 영구 삭제를 수행하지 않는다.

다시 열 때는 저장한 작업 위치를 사용한다. 외부에서 삭제되거나 Git 연결이 손상된 worktree는 연결을 거부하고 원본 폴더로 전환하거나 재생성하지 않는다. 기존 스레드 이동, 변경 가져오기·병합, 경로 설정, 독립적인 worktree 관리 화면·자동 정리는 제공하지 않는다.

## Git 연동 구조

Git 연동은 시스템 Git CLI로 통일한다. `src-tauri/src/git.rs`는 셸 없이 실행 파일과 인자를 전달하고, 실행 실패와 Git의 실패 종료를 구분하며 종료 상태와 stderr를 보존한다. Git 훅 등에서 상속한 저장소 전용 환경변수는 제거하여 다른 저장소의 Git 경로·인덱스·설정이 조회 대상에 섞이지 않도록 한다. stdout은 UTF-8 변환이나 공백·개행 제거 없이 바이트로 반환한다. 비동기 실행과 blocking worker용 동기 실행은 같은 실행 설정과 결과 처리를 사용한다.

`worktree.rs`는 저장소 조건 조회, detached checkout 생성, 실패 시 안전한 정리와 재연결 검증을 담당한다. 조회 결과의 문자열 해석과 사용자 오류 변환은 이 계층에 둔다.

향후 커밋 목록·브랜치·히스토리 그래프·diff 기능도 같은 Git 실행부를 사용한다. 명령별 출력 해석은 Rust에서 수행하고 프런트엔드에는 구조화한 데이터를 전달한다. 각 기능을 추가할 때 필요한 조회와 데이터 타입을 도입하며, Git 라이브러리와 CLI를 혼용하지 않는다.
