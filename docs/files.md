# Files 탭

우측 프로젝트 패널에서 Files 탭을 연다. Files는 스레드마다 하나를 재사용하며 해당 작업 폴더를 탐색한다. 트리와 파일 뷰는 나란히 표시하고 내부 구분선으로 폭을 조절한다.

트리의 파일 아이콘은 밝고 어두운 테마 모두에서 파일 종류별 색상으로 표시한다. Pierre의 `complete` 아이콘 세트와 컬러 옵션을 사용한다.

경로 검색은 대소문자를 구분하지 않으며 검색창에는 사용자가 입력한 대소문자를 그대로 표시한다.

`.git`을 포함한 실제 파일, 숨김 파일, ignore된 파일, 빈 폴더를 표시한다. `.git` 내부도 다른 경로와 똑같이 열람·편집·조작할 수 있다. 폴더 링크는 따라가지 않는다. 작업 폴더 내부 파일을 가리키는 링크는 읽기 전용이다. 텍스트 표시·편집은 최대 2MiB의 UTF-8 일반 파일을 지원한다. 문서 렌더링과 Git 상태 표시는 제공하지 않는다.

스레드를 선택하면 작업 폴더의 최상위 항목만 비동기로 읽는다. Files 탭은 이 목록을 재사용하고 폴더를 처음 펼칠 때 바로 아래 항목을 읽어 캐시한다. 파일 본문은 파일을 선택할 때만 읽는다. 폴더 읽기 실패는 해당 폴더에 표시하고 다시 펼치거나 새로고침하면 재시도한다. 경로 검색을 시작하면 펼치지 않은 폴더까지 전체 경로를 탐색해 검색 세션 동안만 보관하며 검색을 닫으면 해제한다.

## 이미지 미리보기

PNG·JPG/JPEG·GIF·WebP·BMP·ICO는 최대 20MiB까지 읽기 전용으로 표시한다. 확장자는 대소문자를 구분하지 않으며, Rust에서 파일 시그니처와 일치하는지 검사한다. 이미지는 원본 크기를 넘지 않게 패널에 맞춰 축소하고 투명 영역에는 테마에 맞는 체크무늬를 표시한다. 로딩·읽기 실패·크기 초과·디코딩 실패를 안내한다. 확대·이동, 이미지 편집과 HEIC·RAW 변환은 제공하지 않는다.

SVG는 기존 UTF-8 텍스트와 같은 2MiB 제한을 적용한다. 기본은 미리보기이며 헤더의 소스·미리보기 버튼으로 전환한다. 미저장 편집도 미리보기에 반영하고, 미리보기 중 수정은 200ms 동안 합쳐 반영한다. 저장·외부 변경 충돌·종료 시 편집 확인은 다른 텍스트와 같다. SVG는 Blob URL을 사용하는 `<img>`로만 표시하며 원문을 DOM에 삽입하지 않는다.

현재 보이는 이미지 한 장만 유지한다. 파일 전환·패널 숨김·종료 시 Blob URL을 해제하고, 외부 수정·내부 이동·패널 재표시 시 다시 읽는다. 삭제·읽기 실패 시 이전 이미지를 제거한다. 20MiB는 원본 bytes 제한이며, 디코딩된 이미지·WebView·GPU 메모리의 상한은 아니다.

## 편집과 파일 조작

텍스트 파일을 선택하면 바로 편집할 수 있다. 저장 버튼 또는 macOS의 ⌘S로 명시적으로 저장한다. 파일별 미저장 편집은 앱 실행 중 메모리에 보존하며, 파일·탭·스레드를 전환해도 유지한다. Files 탭 닫기, 스레드 삭제, 앱 종료 시 모두 저장·버리기·취소 중 하나를 선택한다. 저장 실패나 외부 변경 충돌이 있으면 해당 동작을 취소한다. 비정상 종료나 앱 재시작 뒤 편집 내용 복구는 제공하지 않는다.

트리 상단에는 새 파일·새 폴더·새로고침 버튼을 제공한다. 항목의 우클릭 메뉴에서 생성·이름 변경·휴지통 이동을 수행한다. 이동은 트리 내부 드래그 앤 드롭으로 수행한다. 생성 위치는 선택한 폴더이며 파일 선택 시 부모 폴더, 미선택 시 작업 폴더 루트이다. 기존 이름 덮어쓰기와 폴더를 자신의 하위로 옮기기는 허용하지 않는다. 내부 이름 변경·이동 시 미저장 편집도 새 경로로 유지한다. 휴지통 이동에 실패해도 영구 삭제하지 않는다.

Pierre의 폭이 0인 메뉴 슬롯에 맞춰 항목 메뉴 내용 자체의 폭을 명시한다.

트리의 항목·검색창·메뉴를 제외한 빈 공간에 파일·폴더를 놓으면 작업 폴더 루트로 이동한다. 드롭할 수 있을 때 트리 테두리를 강조한다. Pierre의 현재 버전이 처리하지 않는 빈 공간 드롭만 래퍼에서 보완하며, 항목 위 드롭은 Pierre가 처리한다. 외부에서 끌어온 항목은 이 경로로 이동하지 않는다.

## 외부 변경과 저장 경계

Files가 보이는 동안 파일시스템 알림을 구독한다. 감시를 시작한 뒤 최상위 항목을 다시 확인하고, 변경 알림이 오면 이미 읽은 관련 디렉터리만 실제 디스크 상태와 대조한다. 다시 표시하면 캐시를 먼저 보여주고 읽었던 디렉터리와 열린 파일을 재검증한다. 수정하지 않은 파일에는 외부 변경을 반영하고 미저장 파일에는 충돌을 표시한다. 충돌 화면에서 디스크 내용을 비교·복사하거나 편집을 버리고 다시 읽는다. 외부 이름 변경을 식별하지 못하면 삭제·생성으로 처리하고 기존 편집은 보존한다.

Rust는 읽은 bytes의 해시를 기준 버전으로 반환하고 저장 직전에 다시 비교한다. 원본 권한·줄바꿈·UTF-8 BOM을 보존해 같은 디렉터리의 임시 파일을 원본과 교체한다. 앱 내부 파일 조작은 직렬화하지만 외부 프로세스를 잠그지는 않으므로 최종 버전 검사와 교체 사이에 외부 쓰기가 발생할 가능성은 있다.

## 구현 경계

`features/workspace-files`가 파일별 편집과 파일 명령·확인 UI를 소유한다. `shared/ui`의 Pierre 래퍼가 트리와 파일 렌더러 수명을 관리한다. 트리는 `@pierre/trees`의 vanilla API, 텍스트 편집은 기존 `@pierre/diffs/edit`를 사용한다. 초기 최상위 경로 목록의 Pierre 입력 준비는 Worker에서 실행하고, 최신 초기 목록을 적용한 뒤 Worker를 종료한다. 첫 디스크 목록을 받기 전의 빈 목록으로는 초기화를 완료하지 않는다. 새로고침 중에는 기존 트리 인스턴스와 상태를 유지한다. 폴더 펼침은 Pierre 구독으로 감지하고 자식 항목은 공개 `batch()` API로 반영한다.

`resetPaths()`는 초기 목록 적용에만 사용한다. 이후 목록은 현재 트리 경로와 비교해 추가·삭제만 공개 `batch()` API에 전달한다. 삭제된 폴더의 하위 항목은 중복 삭제하지 않는다. 공개 변경 이벤트로 Pierre가 먼저 반영한 이름 변경·이동을 추적해 디스크 확인 이벤트를 중복 적용하지 않는다. 이동 실패는 역방향 `move()`와 최신 목록 대조로 복구한다. 미저장 표시는 경로 모델을 갱신하지 않고 기존 인스턴스의 `render()`로 화면만 갱신한다.

Trees `1.0.0-beta.6`는 정규화한 소문자 검색어를 입력창에도 표시한다. `patches/@pierre__trees@1.0.0-beta.6.patch`를 pnpm에 등록해 입력 원문과 검색용 정규화 값을 분리한다. 설치 시 같은 패치가 적용되며, 버전 갱신 시 이 동작을 재검증한다.

Pierre의 폴더 경로는 끝에 `/`가 붙는다. 래퍼는 선택·항목 메뉴·이름 변경·드래그 이동에서 이를 제거해 Atte의 상대 경로 형식으로 전달한다. 하위 미저장 파일 판별과 생성·이동 경로 결합은 이 형식을 기준으로 처리한다.

선택 경로 변경은 목록 갱신과 별개로 Pierre의 공개 선택 API에 즉시 반영한다. 이전 강조는 해제하며 선택 경로가 없으면 강조를 모두 지운다. 초기 Worker 응답이나 이후의 부분 갱신으로 새 경로가 추가된 경우에도 최신 선택을 다시 적용한다. 프로그램에서 적용한 선택은 사용자 선택 이벤트로 되돌려 보내지 않으며, 이전에 대기 중이던 선택 이벤트가 최신 선택을 덮어쓰지 않도록 한다.

메인 웹뷰는 `dragDropEnabled: false`로 Tauri의 네이티브 파일 드롭 가로채기를 끄고 Pierre의 HTML 드래그 이벤트를 사용한다. 파일 첨부는 기존 선택창 경로를 사용한다. 이 설정은 네이티브 웹뷰 설정이므로 변경 후 앱을 재시작해야 한다.

Rust의 `workspace_files` 모듈은 스레드 ID로 작업 폴더를 확인하고 상대 경로를 검증한다. 한 단계 디렉터리 조회와 전체 경로 검색은 별도 명령이며, 탐색 구독은 Tauri Channel로 최상위 스냅샷과 변경 경로를 전달한다. 파일 읽기·버전 확인 저장·생성·이동·휴지통도 별도 명령으로 제공한다. 감시는 `notify`, 휴지통 이동은 `trash`를 사용한다. macOS에서는 Finder 자동화 권한을 요구하지 않는 `NSFileManager` 방식을 명시한다. 이미지 읽기는 같은 경로 검증 후 바이너리 IPC 응답을 반환하며 프런트엔드에서 Blob URL로 표시한다. 원격 웹 탭에는 파일 명령 권한을 부여하지 않는다.
