# Git 패널

프로젝트 패널의 새 탭에서 `Git`을 선택한다. 같은 스레드의 Git 탭은 재사용한다. 기본 내부 탭은 `Changes`이며 `History`와 전환할 수 있다. 각 탭의 브랜치 선택 줄 오른쪽에 새로고침 버튼을 둔다. 저장소 하위 폴더와 linked worktree도 지원한다.

## 작업 변경 사항

`Changes` 안에는 History와 같은 위치에 브랜치 선택 영역을 둔다. 작업 변경은 현재 작업 폴더에만 존재하므로 선택 가능한 범위는 해당 폴더에 체크아웃된 브랜치 하나다. detached HEAD도 명시한다. 파일별 박스를 기본으로 펼쳐 diff를 한 스크롤 영역에서 보여준다. 각 박스는 파일명·상위 경로·상태·변경 줄 수를 표시하며, 부분 staging된 파일은 staged와 unstaged 박스에 각각 나타난다. 미추적 파일은 Changes에 포함하며 ignored 파일은 제외한다. 바이너리 파일의 줄 수는 `—`로 표시한다. 파일별 patch는 접고 펼쳐도 재요청하지 않고 실제 파일 상태가 바뀌면 갱신한다. 충돌 파일은 별도로 안내한다.

체크박스는 작업 대상을 선택하며 Shift+클릭으로 범위를 선택한다. 우클릭에서 선택 항목을 Stage, Unstage, Restore 또는 Trash할 수 있다. 상단 메뉴에서 Stage All, Unstage All, Restore All Changes, Stash All, Stash Pop을 실행한다. Restore는 선택한 tracked 파일의 staged·unstaged 변경을 모두 HEAD로 되돌리고 새 staged 파일은 휴지통으로 보낸다. 원래 untracked였던 파일은 Restore All에서도 보존한다. Trash는 실제 파일을 시스템 휴지통으로 보내고 index를 보존한다. Stash All은 untracked 파일도 포함하며 Stash Pop은 최신 stash를 일반 Git 동작으로 적용한다. Restore와 Trash는 실행 전 확인한다. Commit 버튼은 Dialog에서 커밋 제목과 선택적 본문을 받고 staged 변경만 커밋한다. 초안은 앱 실행 중 작업 폴더별로 유지하고 성공 시 지운다.

Git 패널이 보이고 앱에 포커스가 있을 때 2초마다 상태를 갱신한다. 포커스 복귀와 수동 새로고침 시에도 조회한다. 같은 작업 폴더의 앱 내부 Git 조작은 직렬화한다. 커밋 직전 HEAD와 index tree가 확인한 상태와 달라지면 커밋을 거부하고, Restore·Trash·Stash는 확인한 상태가 달라지면 거부한다. 충돌 또는 merge/rebase/cherry-pick 등의 진행 중인 작업은 조회만 가능하다. Amend, 브랜치 전환, push/pull, 줄·hunk 단위 staging은 제공하지 않는다.

## 이력 탐색

기본 범위는 로컬 브랜치·원격 추적 브랜치·태그 및 현재 HEAD에서 도달 가능한 커밋이다. 브랜치 선택은 해당 브랜치와 공통 조상의 이력으로 표시 범위를 좁힌다. checkout은 하지 않는다. 원격 추적 브랜치는 로컬에 저장된 상태이며 새로고침도 fetch하지 않는다. reflog와 stash 전용 이력은 포함하지 않는다.

첫 표시 때 200개를 읽고, 스크롤이 목록 끝에 가까워지면 다음 페이지를 읽는다. 전체 커밋 수를 미리 계산하지 않는다. Rust는 조회 시작 시 ref의 OID를 고정한 Git 로그 스트림을 유지하고, 출력 파이프의 backpressure로 전체 로그를 메모리에 모으지 않는다. 화면에서는 Solid Virtual로 보이는 행과 주변 일부만 렌더링한다. 그래프는 페이지 사이에 미조회 부모의 레인 상태를 유지한다.

History는 최초 진입과 새로고침 버튼으로 갱신한다. 외부에서 HEAD가 바뀌면 갱신 안내를 표시한다. 탭 전환과 패널 접기는 조회한 이력과 스크롤 상태를 보존한다. 브랜치 변경과 새로고침은 새 조회를 시작하고 이전 결과를 무시한다. 탭 닫기·스레드 삭제·창 종료는 남은 Git 로그 스트림을 정리한다. 페이지 로딩 실패 시 이미 읽은 이력은 유지하며 새로고침으로 조회를 다시 시작한다.

## 커밋 변경사항

커밋 선택 시 해당 저장소와 커밋의 별도 diff 탭을 연다. 같은 커밋을 다시 선택하면 기존 탭을 선택한다. 일반 커밋은 부모와, merge는 첫 부모와, 최초 커밋은 빈 tree와 비교하며 기준을 표시한다. Shallow clone의 이력 경계에 부모 객체가 없으면 최초 커밋으로 취급하지 않고 diff를 제공할 수 없는 이유를 안내한다.

커밋 정보와 변경 파일 목록, 파일별 추가·삭제 줄 수를 먼저 조회한다. 파일은 세로로 배치한 박스에서 기본으로 모두 펼쳐지며, 각 화살표로 개별 접기·펼치기와 상단 버튼으로 전체 접기·펼치기를 제공한다. 상단과 각 파일 헤더에 변경 줄 수를 표시하고 바이너리 파일의 줄 수는 `—`로 나타내며 전체 합계에서 제외한다. 파일 이름 클릭은 아직 동작하지 않는다. 파일별 patch는 별도로 읽고 접었다 펼쳐도 재조회하지 않는다. 기존 `@pierre/diffs` 렌더러를 사용하며 전체 소스를 읽지 않은 patch에서는 전체 코드 보기를 제공하지 않는다. 펼친 영역에는 경로·mode·OID 헤더를 중복 표시하지 않고 diff 또는 상태 안내를 바로 보여준다. 바이너리·submodule·UTF-8 이외의 텍스트·2 MiB를 초과하는 파일 또는 patch는 상태를 안내한다.

Git 명령은 Rust에서 스레드의 작업 폴더를 확인한 뒤 실행한다. WebView에는 임의 경로나 명령 실행 API를 제공하지 않는다. 이력 및 탭 상태는 앱 실행 중에만 유지하며 DB에 저장하지 않는다. 에이전트가 보고한 턴별 `Changes` 탭의 동작은 유지한다.
