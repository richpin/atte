# Use ACP config options for thread configuration

Atte는 모델·추론 수준·동작 모드를 에이전트별 필드로 정의하지 않고, 에이전트가 ACP v1 `configOptions`로 제공한 `select`와 `boolean` 설정을 범용적으로 표시한다. 입력창에는 Category나 설정 개수에 관계없이 모든 설정을 개별 control로 나열하고, 공간이 부족하면 다음 줄로 배치한다. 이번 범위에서는 deprecated `modes` fallback, 설정 기본값의 영구 저장, 설정 이름을 근거로 한 Atte 자체의 자동 승인 정책을 제공하지 않는다. 사용자의 선택은 프롬프트 전송까지 보류하지 않고 즉시 적용하며, UI에는 pending 상태를 따로 노출하지 않고 선택값을 곧바로 표시한다. 같은 표시값의 선택은 요청하지 않고, 연속 변경 중에도 다른 control은 계속 사용할 수 있게 하되 스레드별 요청을 직렬화하고 아직 전송하지 않은 동일 설정은 마지막 선택으로 합친다. 각 응답에서는 에이전트가 반환한 전체 option snapshot을 반영하고 다음 선택의 유효성을 다시 검사한다. 설정 변경 실패는 스레드 실패로 확대하지 않고 마지막으로 확인된 snapshot으로 되돌리며, 연결 중에는 이전 설정을 현재값처럼 표시하지 않는다. 이렇게 하면 Atte가 확실히 지원할 수 있다고 에이전트가 광고한 설정만 노출하면서 종속된 옵션의 변화도 그대로 수용할 수 있다.


같은 에이전트의 새 스레드에는 이번 앱 실행에서 사용자가 마지막으로 성공적으로 변경한 설정 응답의 전체 현재값을 적용한다. 에이전트 ID별로 백엔드 메모리에만 보관하고 작업 폴더와 무관하게 사용하며 앱 종료 시 초기화한다. 새 ACP 세션 생성 후 준비 상태로 전환하기 전에 제공된 설정 순서대로 적용하고, 각 응답의 전체 snapshot을 기준으로 다음 값의 유효성을 다시 검사한다. 없는 설정·유효하지 않은 값·이미 같은 값은 건너뛴다. 에이전트가 설정 변경을 거부하면 나머지 설정을 계속 적용하고 스레드 안내를 표시한다. 기존 스레드의 재개에는 최근 설정을 덮어쓰지 않으며, 새 스레드 생성·기존 스레드 재개·자동 적용·실패한 변경은 기억한 기본값을 갱신하지 않는다.
