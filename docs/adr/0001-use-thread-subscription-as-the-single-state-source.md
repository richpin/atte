# 스레드 상태는 구독을 단일 공급원으로 사용한다

사이드바 스레드 메뉴의 이름 변경은 현재 표시 제목이 선택된 다이얼로그에서 편집한다. Enter·저장으로 확정하고 Escape·취소로 닫으며 공백만 있는 제목은 허용하지 않는다. `rename_thread`는 앞뒤 공백을 제거한 제목을 기존 `title`에 저장한 뒤 스레드·목록 구독으로 전달하고 성공 또는 실패만 반환한다. 저장 실패 시 기존 제목과 편집 입력을 유지한다. 실행·연결 상태와 관계없이 변경할 수 있으며 마지막 입력 시각과 목록 순서는 유지한다. 수동 지정 여부는 따로 저장하지 않고 이후 에이전트의 제목 갱신도 기존대로 적용한다.

스레드를 연 뒤 프런트엔드의 상태는 스레드 구독이 보내는 초기 스냅샷과 이후 변경만으로 구성한다. 변경 명령은 스레드 스냅샷을 반환하지 않고 성공 또는 실패만 알리며, 명령 응답과 구독이라는 두 공급원의 순서를 병합하지 않기 때문에 `Thread.revision`은 제거한다. 여기서 스레드 구독은 프런트엔드와 Atte 백엔드 사이의 상태 전달 경로이며, Atte 백엔드와 에이전트 사이의 연결과 구분한다.

메시지 전송, 응답 중지, 권한 응답 같은 일반 변경 명령은 성공 또는 실패만 반환한다. 새 스레드를 만드는 명령처럼 다음 동작에 식별자가 필요한 경우에는 새 `threadId`만 반환한다. 명령 응답으로 받은 데이터가 프런트엔드의 스레드 상태를 직접 변경하는 경로는 두지 않는다.

스레드 구독이 실패하면 마지막으로 받은 스레드 내용은 화면에 유지하되 메시지 전송, 권한 응답, 응답 중지, 대기 메시지 삭제처럼 백엔드 상태를 바꾸는 모든 명령을 잠시 막는다. 5초 간격으로 최대 5번 새 구독을 만들고, 모두 실패하면 자동 재시도를 중단하고 스레드 헤더 메뉴의 `다시 연결` 항목을 활성화한다. 구독 실패는 스레드 상단의 지속적인 오류 배너로 표시하며 일시적인 오류 알림을 중복으로 띄우지 않는다. 메뉴를 통한 구독 복구 후 에이전트 연결도 실패하거나 끊긴 상태이면 연결을 다시 시도한다. 새 구독의 현재 스냅샷을 받으면 프런트엔드 상태를 다시 맞추고 변경 명령을 허용하며 재시도 횟수를 초기화한다.

자동 재시도는 구독 등록 실패처럼 프런트엔드가 확인할 수 있는 실패에 적용한다. 이미 연결된 로컬 Tauri 채널이 아무 알림 없이 멈춘 상황을 감지하기 위한 별도의 주기적 생존 신호는 이번 변경에 추가하지 않는다. 재구독할 때 스레드가 더 이상 존재하지 않으면 스레드 목록으로 이동하고 사용자에게 이유를 알린다.

메시지 입력창은 구독 상태와 분리된 로컬 UI 상태로 취급한다. 전송 명령이 성공하면 입력창을 비우고, 실패하면 사용자가 다시 시도할 수 있도록 작성한 내용을 유지한다. 전송된 메시지를 대화 목록에 직접 추가하지는 않으며, 대화 목록에는 구독으로 받은 상태만 반영한다.

구독 복구와 에이전트 재연결은 서로 다른 동작이다. 구독이 정상이고 스레드가 준비·연결 끊김·실패 상태일 때 헤더 메뉴의 `다시 연결`은 에이전트 측 연결을 재개한다. 기존 `connect_thread`는 연결된 상태에서 중복 연결하지 않으며, 명시적인 `reconnect_thread`는 준비 상태의 기존 연결을 교체하고 같은 원격 세션을 재개한다. 실행·승인 대기·중지 중에는 재연결을 허용하지 않는다. 원격 세션이나 다른 스레드의 공유 프로세스는 삭제하지 않으며, 이전 연결의 종료 이벤트는 generation 검증으로 새 연결에 영향을 주지 못하게 한다.

백엔드가 오래된 에이전트 실행 결과를 거부하기 위해 내부에서 사용하는 `generation`은 유지한다. 이는 프런트엔드 상태의 변경 순서를 비교하던 `Thread.revision`과 목적이 다른 안전장치다.

프런트엔드와 백엔드는 한 변경에서 함께 새 방식으로 전환한다. 기존 스냅샷 반환 방식과 새 구독 전용 방식을 동시에 지원하는 호환 계층은 만들지 않는다.

오류 이벤트는 변경 패치의 `errors`에 발생별 식별자와 함께 실어 보낸다. 연결 실패는 이벤트의 `failure`와 스레드의 현재 연결 실패로 전달하고, 요청 실행 실패는 이벤트의 `message`로만 전달한다. 요청 실패는 스레드·목록 정보·저장 스키마의 실패 범주에 포함하지 않는다. 현재 연결 실패 또는 저장 오류에 해당하는 이벤트는 배너나 로그인 안내로 전달하므로 일시적인 오류 알림을 중복으로 띄우지 않는다. 요청 실패와 현재 상태에 남지 않는 오류 이벤트는 일시적인 오류 알림으로 전달한다. 전송 명령 자체가 접수를 거부하면 명령 오류로만 알리고, 접수된 요청의 실행 실패는 구독 이벤트로 알린다. 초기 스냅샷에는 오류 이벤트를 싣지 않으므로 탐색·언어 변경·재구독이 과거 오류를 다시 알리지 않는다. 같은 문구의 새로운 실패는 다른 식별자로 전달하며, 프런트엔드는 이미 처리한 식별자를 다시 표시하지 않는다. 연결 실패 이벤트를 받은 뒤 같은 연결 명령이 실패해도 일시적인 오류 알림을 추가하지 않는다.

스레드 상단에는 현재 연결 실패·저장 오류·스레드 구독 오류를 지속적으로 표시한다. 표시 내용은 구독 상태와 스냅샷·패치의 현재 오류에서 직접 도출하므로 스레드에 다시 진입해도 원인을 확인할 수 있고, 복구가 확인되면 해당 표시를 제거한다. 연결·구독 오류에는 기존 허용 조건을 따르는 `다시 연결` 버튼을 제공하며, 에이전트가 제거되었거나 실행 파일이 없으면 에이전트 관리로 안내한다. 로그인 안내가 열려 있으면 배너를 숨긴다.

스레드 스냅샷·패치와 목록 정보는 이번 앱 실행에서 마지막으로 정상 종료한 응답의 `completedTurnId`를 전달한다. 취소 의도가 있는 종료·요청 실패·연결 오류는 새 완료를 만들지 않는다. 정상 완료는 텍스트가 없어도 기록하고 다음 대기 메시지를 실행하기 전에 갱신한다. 이 필드는 저장하지 않고 과거 대화에서도 재구성하지 않는다. 일반 요청 실행 실패는 정상 연결을 종료하지 않으며, 실패한 대기 메시지는 그대로 보존해 재시도할 수 있게 한다. 인증 필요나 통신 종료는 요청 실행 중에도 연결 실패로 처리한다.

프런트엔드는 스레드별 확인한 완료 턴 ID를 메모리에 보관한다. 실제 스레드 페이지에 진입하거나 열린 페이지에서 새 완료를 수신하면 앱 포커스·스크롤과 무관하게 확인하며 설정·에이전트 관리 화면에서는 확인하지 않는다. 삭제 시 확인 정보도 제거한다. 사이드바 표시는 구독 오류·연결 오류, 승인 요청, 연결/복원/응답/중단 진행, 미확인 완료 순서로 우선하며, 가려진 완료 정보는 보존한다. 인증 필요는 연결 실패 상태에 유지하되 로그인 필요 자체는 사이드바 상태 표시를 만들지 않고 스레드 안의 로그인 안내로 전달한다. 요청 실패는 사이드바 오류 표시를 만들지 않는다. 행 호버·키보드 포커스는 상태 아이콘 대신 메뉴를 표시하고 승인 배지는 유지한다. 매 요청이 running 또는 waitingForApproval 상태인 동안 대화 영역의 현재 응답 항목들 아래에 에이전트 아이콘을 유지한다. 첫 응답 수신이나 청크 사이의 일시적인 갱신 중단으로 아이콘을 숨기지 않아 응답이 계속 진행 중임을 알린다. 승인 대기와 동작 줄이기에서는 정적으로 표시하며, 완료·취소·연결 실패·구독 오류 시에는 숨긴다.

응답은 답변 텍스트·추론·도구 호출·작업 계획을 수신 순서대로 유지하는 `responseParts`로 표현한다. 연속된 텍스트 청크는 같은 항목에 누적하고 새 추론·도구 호출·계획 뒤의 답변 텍스트는 별도 항목으로 시작한다. 같은 ACP 호출 ID의 부분 업데이트는 최초 위치의 호출을 갱신하며, 생략된 필드는 유지하고 content·locations 배열은 제공된 값으로 교체한다. 구독의 `textDelta`에는 항목 ID를 포함하고 `toolUpdate`는 병합이 끝난 도구 항목을 전달한다. 스냅샷과 기록 복원에는 전체 항목을 포함한다. 기록은 에이전트의 ACP replay로 복원하며 로컬 DB에 본문을 저장하지 않는다.

도구 호출은 기본적으로 접힌 행에 종류 아이콘·제목·펼침 표시·상태를 표시하며 펼침 표시는 제목 바로 뒤에 둔다. 펼치면 입력, 텍스트 결과, 원시 결과와 관련 파일 위치를 일반 텍스트로 표시하며 Markdown으로 해석하지 않는다. 실패 결과도 펼친 상태에서만 표시하고 접힌 행에는 실패 상태만 표시한다. 도구 완료 체크 아이콘은 라이트·다크 테마의 성공 색상(녹색)으로 표시한다. 파일 diff·터미널·미디어는 도구 호출 행 내부에서 종류와 가능한 경로만 안내한다. 파일 diff는 턴 변경 요약과 사이드 패널에서 검토하며 터미널·미디어 전용 미리보기는 제공하지 않는다. 승인 요청에는 도구 호출 ID를 연결해 해당 행에 승인 필요를 표시하고 기존 입력창에서 판단을 받는다. 취소 중에는 최종 도구 업데이트를 계속 수신하되 텍스트 청크를 추가하지 않는 기존 동작은 유지한다. 응답이 종료되면 미완료 호출의 진행 애니메이션을 멈추고 중단 여부에 따라 중단됨 또는 완료 상태 미확인으로 표시한다. 도구 실패 자체를 스레드 요청 실패로 취급하지 않는다. 도구 호출은 묶음으로 접지 않고 모두 개별 행으로 표시한다. 도구 호출·추론·작업 계획·계획 문서의 박스는 `rounded-xl`로 맞추고 도구 호출·추론의 헤더 행은 위아래 패딩을 각각 4.5px로 맞춘다. 작업 계획·계획 문서의 헤더 행은 위아래 패딩을 각각 12px로 하고 제목을 16px 크기의 굵은 글씨로 표시한다. 두 계획 헤더는 앞에 전구 아이콘을 두고 펼침 표시를 제목 바로 뒤에 둔다. 도구 호출과 추론의 행이 연속되면 조합과 관계없이 사이 간격을 4px로 줄인다. 답변·계획 등 다른 항목과의 간격은 기존 20px를 유지한다.

작업 계획은 턴당 하나의 카드로 표시한다. ACP plan 전체 스냅샷을 최초 위치의 같은 ID에 교체하고 구독의 `planUpdate`로 해당 항목만 전달한다. 실시간 응답과 ACP replay는 같은 누적 로직을 사용한다. 빈 계획은 화면에서 숨기되 ID와 위치는 유지한다. 카드는 처음 펼쳐서 표시하고 갱신 중 사용자의 펼침 상태를 보존한다. 항목의 내용·순서를 그대로 일반 텍스트로 표시하며 완료 수와 상태 아이콘을 제공한다. 접힌 상태에는 첫 진행 중 항목을 표시한다. 종료·취소·연결 중단 시 진행 애니메이션만 멈추고 마지막 상태는 유지한다. 취소 중 마지막 계획 갱신도 수용한다.

추론은 `agent_thought_chunk`의 텍스트를 별도 thought 항목에 누적하며 일반 답변 텍스트에 포함하지 않는다. 연속 청크는 병합하되 새로운 응답 항목 또는 이전의 알려진 ACP messageId와 다른 ID가 경계를 만든다. messageId가 생략된 청크는 현재 항목에 누적하고 알려진 ID를 유지한다. ID와 원문 처리 규칙은 실시간 수신과 replay에서 공유하며 원본 messageId는 백엔드 내부에만 둔다. 빈 문자열과 텍스트 이외의 추론 content는 항목을 만들지 않는다. `thoughtDelta`는 항목 ID와 추가 텍스트만 전달하며 전체 스냅샷과 기록 복원에는 누적된 내용을 포함한다. 취소 후 추론 청크는 일반 텍스트처럼 무시하고 이미 받은 내용은 유지한다. 에이전트가 과거 추론을 replay하지 않으면 로컬에서 복원하지 않는다.

계획 문서는 ACP v1의 Draft Plan Operations 확장(`unstable_plan_operations`)을 사용한다. 초기 연결에서 `clientCapabilities.plan`을 선언하고 `plan_update`·`plan_removed`를 처리한다. 확장 형식은 ACP 경계에서 내부 `PlanContent`로 변환하며 `responseParts`의 `planContent`와 구독의 `planContentUpdate`로 전달한다. 같은 세션의 `planId`는 턴이 달라져도 최초 위치와 표시 ID를 유지하며 전체 스냅샷으로 갱신한다. 제거된 계획은 본문을 비워 숨기되 항목의 위치와 ID는 남긴다. 실시간 응답과 이력 재생은 같은 누적 로직을 사용하며, 이전 턴의 계획 갱신은 해당 소유 턴으로 전달한다. 기존 ACP `plan` 작업 목록은 별도로 유지한다.

계획 문서는 대화 안의 기본적으로 펼친 접이식 카드로 표시한다. Markdown은 기존 렌더러로 표시하고 항목형 계획은 기존 작업 목록 UI를 재사용한다. 파일형 계획은 참조 URI만 일반 텍스트로 표시하며 자동으로 파일을 읽거나 열지 않는다. 빈 본문·빈 목록·제거된 계획은 숨기고 갱신·제거·복원 중 사용자의 접힘 상태를 유지한다. 승인 요청은 기존 도구 및 승인 UI에서 처리한다. 에이전트 이름, 메시지 문구, 도구의 승인 본문을 근거로 일반 응답을 계획 문서로 추측하지 않는다. [ACP Plan Operations 제안](https://agentclientprotocol.com/rfds/plan-operations)은 아직 Draft이므로 해당 확장을 구현한 에이전트에서만 전용 문서 카드가 제공된다.

일반 승인 요청의 상세 내용은 입력창에 기본으로 표시한다. Codex의 계획 승인은 ACP 경계에서 `switch_mode` 종류, `plan-review:<planId>` 호출 ID, `implement_plan`·`revise_plan` 선택지와 단일 `rawInput.plan` Markdown 본문으로 식별한다. 선택지는 각각 `allow_once`·`reject_once`여야 하며, 추가 입력·내용·파일 위치가 있으면 일반 승인처럼 표시한다. 같은 계획 ID의 Markdown 문서가 대화에 있고 승인 대상 본문과 정확히 일치할 때만 입력창의 중복 상세 내용을 숨기고 제목·선택지를 유지한다. 문서가 없거나 비어 있거나 제거되었거나 내용이 다르면 상세 내용을 표시한다. 계획 승인 식별 정보는 메모리의 승인 요청에만 포함하며 승인 선택지와 응답 전달은 기존 방식을 유지한다.

추론 영역은 기본적으로 접혀 있고 펼친 동안만 기존 Markdown 렌더러로 원문을 표시한다. 사용자의 펼침 상태는 청크 추가나 응답 종료로 변경하지 않는다. 제목은 상태와 관계없이 생각 중(Thinking)으로 표시하며 펼침 표시는 제목 바로 뒤에 둔다. 현재 턴의 마지막 항목이 추론이고 구독·에이전트 연결이 정상인 running 상태일 때만 진행 아이콘을 활성화하며, 승인 대기·취소·완료·연결 실패 시 진행 표시를 멈춘다. 도구와 계획의 제자리 업데이트는 추론의 위치나 누적 경계를 바꾸지 않는다.

컨텍스트 사용량은 ACP `usage_update`의 used·size 최신 값을 스레드의 메모리 상태와 snapshot·patch에 포함한다. 턴과 독립적으로 갱신하며 누적 합산하지 않는다. 응답 종료와 화면 이동 뒤에는 유지하고 재연결 시작 시 초기화한다. DB에 저장하지 않으며 이전 런타임의 이벤트는 generation 검사로 배제한다. Thread 페이지 폭과 관계없이 우측 상단의 고정 240×128px 카드에 Context 사용률·토큰 수와 Progress bar를 기본 표시한다. Context 제목은 14px, 아래 사용량·안내 문구는 12px로 표시한다. 정보가 없거나 size가 0이면 안내를 표시한다. 스레드 헤더 메뉴 왼쪽의 List 아이콘 토글로 카드 표시를 전환한다. 두 헤더 버튼은 4px 간격으로 배치하고 호버·선택 배경과 툴팁에는 테마의 메뉴 배경색을 사용한다. 라이트 테마에서는 흰 배경으로 표시하며 툴팁의 테두리를 제거하고 키보드 포커스에는 옅은 테두리 색상의 링을 사용한다. 표시 상태는 프런트엔드의 로컬 UI 상태로 모든 스레드와 화면 이동에 걸쳐 앱 실행 중 유지하며 재시작 시 표시로 초기화한다. 카드를 숨긴 동안에도 구독에서 사용량을 갱신하므로 다시 표시하면 최신 값을 보여준다.

턴 변경 요약은 ACP v1 diff의 path·oldText·newText를 사용하며 완료된 도구 호출만 집계한다. 진행·승인 대기·실패한 호출은 제외하고 취소된 턴도 완료된 호출은 유지한다. 같은 파일의 전·후 본문이 연결되면 최초 상태와 최종 상태로 합치고 원복된 변경은 제외한다. 불연속한 수정은 순서대로 보존하며 요약 박스·패널 상단·파일 행에 각 수정 내역의 추가·삭제 행 수를 합산해 표시한다. 불연속한 수정도 보고된 각 수정 내역을 합산하되 별도의 수정 건수 문구는 표시하지 않는다. 턴이 종료되면 응답 하단에 요약 블록 하나를 표시하고, 선택하면 기존 패널에 턴별 변경 탭을 연다. 파일은 처음 모두 접혀 있고 여러 파일을 독립적으로 펼칠 수 있다. 펼친 파일에는 Pierre Diffs의 읽기 전용 unified diff를 가상화하여 표시한다. 변경 사이의 숨겨진 원문은 라이브러리의 확장 컨트롤로 방향별 20줄씩 또는 해당 영역 전체를 펼칠 수 있다. 추가로 펼칠 원문이 있는 diff 상단에만 전체 코드 보기·변경 부분만 보기 전환을 제공한다. 추가 원문이 없으면 안내 문구와 전환 영역을 표시하지 않는다. 확장 가능한 내용은 보고받은 원문 범위로 한정하며 현재 파일을 추가로 읽지 않는다. 공용 렌더러는 ACP와 턴을 알지 않고 파일의 두 버전으로부터 준비한 diff를 받는다. 탭은 보고된 내용을 보존하고 현재 파일로 대체하지 않으며 탭·패널 전환 시 펼침 상태와 스크롤을 유지한다. 보고되지 않은 셸 변경은 포함하지 않고 replay에 없는 diff를 로컬 DB에서 복원하지 않는다. 파일 스냅샷·되돌리기·Git 조회는 추가하지 않는다.
