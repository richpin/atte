# Thread 웹 탭은 OS의 자식 웹뷰를 사용한다

Thread 우측 프로젝트 패널의 웹 탭은 앱 UI와 같은 창에 Tauri 자식 웹뷰로 표시한다. macOS에서는 WKWebView를 사용한다. iframe은 사이트의 임베딩 제한 때문에 일반 웹 주소를 지원하기 어렵고 별도 브라우저 엔진은 앱 크기와 관리 비용을 늘리므로 채택하지 않는다. 자식 웹뷰 생성에는 Tauri의 `unstable` Cargo 기능이 필요하다.

대화의 HTTP·HTTPS 링크는 클릭하거나 Enter로 활성화할 때마다 해당 스레드의 새 웹 탭을 열고 패널을 펼친다. 사용자 메시지·답변·추론·계획 문서는 같은 링크 경로를 사용하며 다른 화면의 외부 브라우저 링크 동작은 유지한다. 대화 영역과 패널의 최소 폭은 각각 320px이다. 본문 폭이 640px 미만이면 패널을 숨기고 스레드 대화 영역이 본문 전체를 차지하며 왼쪽 사이드바는 유지한다. 사용자가 패널을 전체 폭으로 확장한 상태에서도 좁은 화면에서는 스레드를 우선 표시한다. 패널의 고정 최대 폭은 두지 않는다. 구분선을 왼쪽으로 옮겨 대화 영역의 최소 폭을 넘어 끌면 대화 영역이 접히고 패널이 본문 전체로 확장된다. 반대로 끌면 대화 영역을 다시 표시한다. 대화와 탭의 내용은 계속 마운트해 입력과 페이지 상태를 보존한다. 창이 다시 640px 이상으로 넓어지면 이전 패널 표시 상태와 분할 폭 또는 전체 폭 상태를 복원한다. 사용자가 직접 확장한 전체 폭 상태는 스레드별로 유지한다. 모든 탭을 닫으면 번호를 초기화한 `새 탭 1`을 표시하고 이후 추가하는 탭은 2부터 순서대로 번호를 부여한다. 새 탭에서 `웹`을 선택하면 그 탭에 주소창을 표시하고 주소 제출 후 웹뷰를 생성한다. 주소창·뒤로/앞으로·새로고침·외부 브라우저로 열기를 제공한다. 네이티브 웹뷰를 생성하는 동안 주소 입력과 제출을 잠시 막아 생성 중 다른 주소가 무시되지 않도록 한다. 스킴 없는 주소는 HTTPS로, localhost·루프백 주소는 HTTP로 보완한다. 검색 엔진으로 전달하지 않는다.

프런트엔드가 탭 순서·선택·크기·표시와 웹뷰 수명을 관리한다. 탭이나 스레드를 전환하거나 패널을 접어도 웹뷰를 종료하지 않고 숨긴다. 닫기·스레드 삭제·창 종료 시 정리하며 생성 중 닫힌 탭의 늦은 결과도 종료한다. 탭과 탐색 이력은 앱 실행 중에만 유지하고 DB에 저장하지 않는다. 쿠키는 WebKit의 Atte 저장소를 사용하며 Safari의 로그인 상태를 공유하지 않는다.

Rust는 생성 시 탐색·새 창·다운로드 정책을 설정하고 주소 이동·새로고침·네이티브 탐색 이력에 연결한다. 현재 Tauri JavaScript API는 이 탐색 기능과 페이지 상태 조회를 제공하지 않는다. macOS 연결은 `objc2-web-kit`의 타입을 사용하며 WKWebView 참조를 Tauri의 메인 스레드 콜백 밖으로 전달하지 않는다. 페이지 URL·제목·로딩·뒤로/앞으로 상태는 표시 중인 탭만 500ms 간격으로 조회하며 앱 대화상자·메뉴 표시를 감시하는 DOM observer도 표시 중인 탭에만 연결한다. WebKit의 navigation delegate를 교체하지 않고 SPA 주소 변경도 반영하기 위한 선택이다. favicon은 같은 조회에서 고정된 읽기 전용 표현식으로 페이지의 `link[rel~="icon"]`을 읽고 상대 주소·미디어 조건을 반영한다. 선언이 없으면 사이트의 `/favicon.ico`를 사용한다. 페이지를 변경하거나 브리지·리스너를 설치하지 않으며 탐색 중 URL이 바뀐 결과는 버린다. 아이콘은 앱 UI에서 이미지로만 표시하며 로드 실패나 아이콘이 없는 새 탭에는 globe를 표시한다. 이를 위해 CSP의 이미지 출처에 HTTP·HTTPS를 허용하며 스크립트·앱 명령 권한은 추가하지 않는다. 변경 검토 탭의 이름은 `Changes`이고 아이콘은 턴 요약 블록과 같은 `file-diff`를 사용한다.

앱 capability는 창 전체가 아니라 `main` 웹뷰에만 부여한다. 모든 앱 명령의 호출자도 `main`으로 제한하며 웹 탭에 원격 명령 권한을 추가하지 않는다. 초기 주소·주소창 이동·페이지 탐색·새 창 요청에서 HTTP·HTTPS와 앱 내부 origin 차단을 Rust가 검사한다. 페이지의 HTTP·HTTPS 새 창 요청은 같은 스레드의 새 웹 탭으로 전환하고 원래 팝업을 차단한다. opener 플러그인의 자동 링크 가로채기는 꺼서 원격 페이지의 `_blank` 요청이 네이티브 처리기에 도달하도록 한다. 앱의 외부 링크는 명시적인 `openUrl`을 사용한다. 다운로드와 별도 팝업 기반 인증은 제공하지 않는다. 생성·명령 실패는 탭 안에 재시도 안내를 표시한다. 생성 후 숨김 처리나 프런트엔드 핸들 조회가 실패하면 이미 만든 웹뷰를 정리해 같은 탭에서 다시 생성할 수 있도록 한다.

네이티브 웹뷰는 HTML 위에 표시되므로 주소창 아래의 영역만 차지하도록 크기·위치를 동기화한다. 화면 전환·패널 접기 및 앱 대화상자·메뉴·선택 목록이 열린 동안 숨겨 입력 충돌을 방지한다. 자식 웹뷰 추가 후에는 Tauri가 해당 창을 `WebviewWindow`로 취급하지 않으므로 기존 앱 명령의 호출자는 `Webview`, macOS 창 재열기는 `Window`로 처리한다.
