# 로컬 DB 구조

현재 스키마: SQLite v1. Rust의 `Store`가 DB 접근과 트랜잭션을 소유하며 설치 관리와 스레드 module이 같은 저장소를 공유한다. 파일 위치는 Tauri 앱 데이터 폴더의 `atte.sqlite`이며, macOS 기본 위치는 `~/Library/Application Support/com.atte.app/atte.sqlite`다. 별도 DB 서버는 없다.

## agents

Registry ID당 한 행에 목록 메타데이터와 현재 설치 정보를 함께 보관한다. 테이블 간 외래 키는 없다.

| 컬럼 | SQL 타입 | 의미 |
| --- | --- | --- |
| `id` | TEXT PRIMARY KEY NOT NULL | Registry 에이전트 ID |
| `registry_metadata` | TEXT, nullable | 이름·설명·아이콘·Registry 버전·배포 정보 JSON. 현재 Registry에 없으면 NULL |
| `installed_version` | TEXT, nullable | 실제 설치한 버전 |
| `artifact_path` | TEXT, nullable | 앱이 관리하는 설치 디렉터리 경로 |
| `launch_definition` | TEXT, nullable | 실행 정의 JSON: id, name, command, args, env |

설치 컬럼 세 개는 모두 NULL이거나 모두 값이 있어야 한다. 미설치 상태는 모두 NULL이다. 실제 파일 유무는 실행 가능 여부를 판단할 때 별도로 확인하므로 DB 기록만으로 설치 성공을 표시하지 않는다.

Registry 갱신은 `registry_metadata`만 트랜잭션으로 교체한다. 목록에서 사라져도 설치 정보가 있으면 행을 유지한다. 목록에도 없고 설치도 없는 행은 제거한다. 캐시 메타데이터 해석 실패가 유효한 설치 정보의 복원을 막지 않는다.

정상 설치에 대한 반복 설치 요청은 그대로 재사용한다. 배포 변경을 비교하는 `installation_source`는 없으며 자동 업데이트하지 않는다. 새 배포를 쓰려면 삭제 후 설치한다. 파일이 없거나 손상되어 재설치하는 경우에도 이전 연결과 남은 설치 파일을 먼저 정리한다.

## app_metadata

| 컬럼 | SQL 타입 | 의미 |
| --- | --- | --- |
| `key` | TEXT PRIMARY KEY NOT NULL | 메타데이터 이름 |
| `value` | TEXT NOT NULL | 값 |

현재 키는 `registry_fetched_at` 하나다. 마지막 정상 Registry 갱신의 Unix 초를 저장한다. 자동 갱신 시도는 메모리의 마지막 시도 시각으로 한 시간 간격을 제한하고, 재실행 시 저장된 정상 갱신 시각을 사용한다.

## 삭제와 실패 복구

스레드 목록과 세션 참조는 설치 정보와 독립적으로 보존한다. 목록을 읽기 위해 에이전트 프로세스나 작업 폴더가 존재할 필요는 없다.

1. 삭제 위치가 앱의 설치 디렉터리인지 검사한다. 공용 `agents/runtime`과 외부 경로는 거부한다.
2. 새 스레드 선택에서 제외하고 해당 에이전트의 모든 연결·작업을 종료한다. 프로세스 종료를 기다린 뒤 파일 삭제를 시작한다. 다른 에이전트는 영향을 받지 않는다.
3. 설치 디렉터리를 즉시 삭제한다. 심볼릭 링크는 대상을 따라가지 않고 링크 자체만 제거한다.
4. 성공하면 설치 컬럼을 NULL로 바꾼다. Registry에 남아 있는 행은 재설치를 위해 유지한다.

파일 삭제 실패 시 설치 정보는 남고 UI에서 삭제 재시도를 할 수 있다. 연결은 이미 종료되었을 수 있다. 파일 삭제 후 DB 반영 전 앱이 종료되면 다음 실행에서 설치 파일 없음으로 표시하며 삭제를 다시 시도하거나 재설치할 수 있다. 없는 경로의 삭제는 성공으로 취급한다. 별도 삭제 대기 테이블이나 재시작 시의 정상 삭제 작업은 없다.

삭제된 설치를 사용한 스레드의 표시 내용은 현재 앱 메모리에 남고, 스레드 메타데이터와 세션 참조는 DB에 남는다. 이전 실행 정의로 재연결하지 않으며 재설치 후 현재 설치 정의로 명시적으로 load/resume을 재시도한다. 에이전트의 기존 세션이 사라졌거나 재개 미지원이면 실패 이유를 표시한다. 작업 폴더·공용 Node·공급자 로그인 정보와 에이전트 소유 세션 기록은 삭제 대상으로 삼지 않는다.

## threads

| 컬럼 | SQL 타입 | 의미 |
| --- | --- | --- |
| `id` | TEXT PRIMARY KEY NOT NULL | Atte가 발급한 스레드 UUID |
| `title` | TEXT NOT NULL | 잠정 제목 또는 에이전트가 제공한 제목; 명시적 해제는 빈 문자열 |
| `working_folder` | TEXT NOT NULL | 작업 폴더의 경로 |
| `agent_id` | TEXT NOT NULL | 스레드에 고정된 에이전트 ID |
| `session_id` | TEXT | 에이전트의 원격 세션 ID |
| `created_at` | INTEGER NOT NULL | 생성 Unix 초 |
| `updated_at` | INTEGER NOT NULL | 로컬 상태 변경 Unix 초 |
| `last_prompt_at` | INTEGER, nullable | 단조 증가하는 마지막 입력 전송 시도 Unix 밀리초; 미전송이면 NULL |
| `status` | TEXT NOT NULL | 마지막 연결·실행 상태 |
| `failure` | TEXT | 마지막 연결·실행 오류 종류 |
| `interrupted` | INTEGER NOT NULL | 이전 작업의 중단 여부, 0 또는 1 |
| `queued_messages` | TEXT NOT NULL DEFAULT '[]' | 제출 순서의 대기 메시지 JSON 배열; 사용자 입력·첨부·상태를 포함 |

메타데이터 저장 interface는 본문을 포함하지 않는 `ThreadMetadata`를 받아 개별 컬럼을 갱신한다. `metadata` JSON 컬럼은 없다. 큐 저장은 `queued_messages`만 갱신하며, 스레드 행이 아직 없으면 메타데이터와 함께 생성한다. 전송된 메시지 본문·도구 출력·승인 이력·실행 핸들·인증 정보는 이 테이블에 저장하지 않는다. 스레드 생성과 상태 변경 시 메타데이터를 저장하고, 응답 텍스트 delta는 메모리에만 반영한다. `lastPromptAt`은 생성 시 NULL이며 대기열 추가나 재진입만으로 갱신하지 않는다. 직접 입력과 대기 메시지 모두 런타임에 전달하기 전에 현재 세션 ID와 전송 시각을 함께 저장한다. 저장 실패 시 전송하지 않으며 직접 입력은 명령 실패로 입력창에 남기고 대기 메시지는 큐에 보존한다. 전송 시도 이후 인증 실패·연결 종료가 발생해도 시각을 되돌리지 않는다. 이 값은 에이전트의 영구 저장 성공을 보장하지 않는다. 목록은 `lastPromptAt ?? createdAt * 1000` 내림차순, 동률이면 ID 오름차순으로 정렬한다. 전송 전 저장 실패는 명령 오류 또는 대기 메시지 오류 알림으로 표시한다. 저장 오류는 현재 스레드 상태의 `storageError`로 표시한다.

새 스레드는 첫 입력 본문의 앞뒤 공백을 제거한 앞 60자를 잠정 제목으로 사용한다. 본문이 없으면 첫 첨부 파일명의 앞 60자를 사용한다. ACP `session_info_update`에서 명시적인 제목을 받으면 전체 문자열을 저장하고 목록과 열린 스레드에 구독으로 반영한다. 제목 필드 생략은 기존 값을 유지하고, `null`은 빈 문자열로 저장하며 화면에는 기본 제목을 표시한다. 동일한 제목은 중복 저장하거나 구독 알림을 보내지 않는다. 명시적인 제목 수신 이후에는 첫 입력·후속 입력이 에이전트 제목을 덮어쓰지 않는다. 첫 입력 제목 적용 여부는 새 draft에만 허용하는 비영속 상태이며, 저장소에서 복원한 스레드에는 다시 적용하지 않는다.

제목 변경은 `lastPromptAt`과 작업 상태에 영향을 주지 않는다. 알림의 `updatedAt`과 `_meta`는 사용하지 않고 Atte의 `updatedAt`은 기존 로컬 상태 변경 시각을 유지한다. 재실행 시 저장된 제목을 복원하고, load/resume 중에도 제목 알림을 처리한다. 에이전트가 재연결 시 최신 제목을 다시 보내지 않으면 저장된 제목을 유지하며, 연결되지 않은 동안의 변경을 별도로 조회하지 않는다.

종료와 재실행 시 `failed` 상태는 보존하며 나머지 연결 상태는 `disconnected`로 복원한다. 이전 실행 중·승인 대기·중단 처리 상태는 중단 여부로 남기며 승인 조작이나 prompt를 되살리지 않는다. 사용자가 스레드를 선택하면 `session/load`를 우선 사용하고 전체 replay 성공 후 메모리의 본문을 교체한다. 실패한 부분 replay는 표시하지 않는다. `resume`만 지원하면 본문 없이 기존 맥락을 이어간다는 안내를 표시한다. 에이전트 부재 시 전체 본문을 읽을 수 있는 디스크 사본은 없다.

연결 시작 전 상태가 `failed`이고 `lastPromptAt`이 NULL이면 다음 Reconnect 또는 재진입에서 원격 세션 참조를 비우고 `session/new`를 호출한다. Atte 스레드 ID와 대기 메시지는 유지하며 새 세션의 설정은 ACP 응답을 사용한다. 실패 직후 자동 재시도는 하지 않는다. 전송 시각이 있으면 기존 세션을 복원하며 실패를 새 세션으로 대체하지 않는다. 초기 스키마 v1만 수정하며 기존 개발 DB 변환·초기화나 과거 값으로 미전송 여부를 추정하는 처리는 하지 않는다.

### 스레드 행의 대기열

각 스레드 행의 `queued_messages` 컬럼에 미전송 입력을 보관한다. Rust 스레드 상태의 잠금 안에서 추가·삭제·전송을 위한 제거를 직렬화하고, 저장 성공 후 메모리와 UI에 반영한다. 배열 순서가 FIFO이며 별도 순서 번호나 전송 상태 테이블은 없다. 빈 대기열은 `[]`로 저장하고 스레드 행은 유지한다.

현재 turn의 `end_turn` 응답에서만 다음 항목을 제거 저장한 뒤 전송한다. 취소 의도가 있거나 비정상 종료한 turn은 다음 항목을 보내지 않는다. 메시지별 전송 시도 기록·결과 불명 상태·자동 재삽입·자동 재전송은 없다. 제거 저장과 실제 전송 사이의 비정상 종료에서는 해당 항목이 유실될 수 있다. 남은 대기열은 재실행·load/resume 이후에도 유지하며 복원 자체로 전송하지 않는다. 이 데이터는 Atte 소유 입력이며 에이전트 스레드 본문의 사본이 아니다.

## 초기 스키마와 버전

출시 전에는 스키마 버전을 v1으로 유지하고 [초기 스키마](../src-tauri/schema.sql)를 직접 수정한다. 새 DB는 이 SQL 하나를 트랜잭션으로 실행하고 `PRAGMA user_version = 1`을 기록한다. 현재 구조의 v1 DB는 그대로 다시 연다. 버전별 업그레이드 마이그레이션은 제공하지 않으며, 이전 개발용 구조의 DB는 호환 대상으로 삼지 않는다. 앱은 기존 DB를 자동 삭제하거나 버전 번호를 낮추지 않는다. 버전이 1보다 높은 DB는 열지 않는다.

## 새로고침과 설치의 갱신 범위

| 동작 | registry_metadata | launch_definition 및 설치 컬럼 |
| --- | --- | --- |
| Registry 새로고침 성공 | 검증된 최신 항목으로 교체 | 유지 |
| 새로고침 실패 | 이전 값 유지 | 유지 |
| 설치 성공 | 유지 | 실제 설치 결과로 기록 |
| 정상 설치에 대한 중복 설치 요청 | 유지 | 기존 값 유지 |
| 삭제 성공 | Registry에 있는 항목이면 유지 | NULL로 비움 |

목록 갱신은 모든 행의 Registry 메타데이터를 비운 뒤 받은 항목들을 ID 기준으로 반영하며, 이 과정 전체와 갱신 시각 저장이 하나의 트랜잭션이다. Registry에서 빠진 항목은 설치되어 있으면 메타데이터 없이 남고, 미설치이면 행을 삭제한다. 새로고침은 실행 중인 프로세스나 기존 스레드의 실행 정의를 바꾸지 않는다. 예를 들어 Registry의 패키지가 2.0으로 바뀌어도 설치된 1.0은 그대로 실행하며, 2.0을 쓰려면 삭제 후 설치한다.
