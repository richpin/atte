# MCP 설정 검증

일반 검증은 `pnpm validate`와 `sh scripts/validate-rust.sh`를 사용한다. MCP 서비스 테스트는 `cargo test --manifest-path src-tauri/Cargo.toml --lib mcp::tests`로 별도 실행할 수 있다.

테스트는 임시 설정 파일과 메모리 자격 증명 저장소를 사용한다. 범위 결합·비활성 제외·원본 폴더와 worktree 작업 위치·비밀값 보존/교체/삭제·자격 증명 실패·외부 편집 충돌·잘못된 파일 보존을 확인한다. Rust ACP fixture가 받은 stdio 설정으로 실제 MCP 프로세스를 실행하여 initialize, tools/list, tools/call을 수행하고, new/load/resume과 공유 런타임 재연결을 검증한다. 세션 설정을 거부하는 에이전트가 자격 증명을 오류에 되돌려 보내도 공개 오류에는 포함하지 않는다.

## OS 및 네트워크 접근이 필요한 테스트

다음 테스트는 기본 suite에서 제외하며 해당 권한이 있는 로컬 환경에서 명시적으로 실행한다. 실제 사용자 서버나 실제 API 키를 사용하지 않는다.

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib mcp::tests::native_credentials_round_trip -- --ignored
cargo test --manifest-path src-tauri/Cargo.toml --lib mcp::tests::http_session -- --ignored
```

첫 테스트는 macOS Keychain 또는 Windows 자격 증명 저장소에 무작위 이름의 임시 자격 증명을 저장·조회·삭제한다. OS 저장소가 잠겨 있거나 샌드박스에서 접근할 수 없으면 실패하며 평문 저장으로 대체하지 않는다.

두 번째 테스트는 일시적인 loopback HTTP MCP 서버를 열고 ACP fixture에 HTTP 지원을 광고한다. Bearer·사용자 지정 인증 헤더를 확인하고 new/load/resume 이후의 실제 HTTP 도구 호출을 검증한다. listener와 에이전트 프로세스는 테스트 종료 시 정리한다.

## 네이티브 UI 확인

앱에서 다음 흐름을 밝은·어두운 테마와 키보드 조작으로 확인한다.

- 앱 메뉴의 MCPs 진입, 전역·프로젝트 선택, 검색, 등록·상세 편집·삭제와 토글.
- 한 행에 하나씩 표시되는 MCP 카드 클릭으로 편집 모달 열기. 카드 토글 왼쪽 새로고침으로 연결 확인·필요 시 OAuth 로그인, 모달 하단 로그아웃, 저장 성공 후 자동 연결 확인과 카드 도구 목록 갱신, 하단 왼쪽 제거·로그아웃과 오른쪽 취소·저장 배치 및 버튼 높이 40px 확인. 도구 목록은 모달에 표시하지 않으며 카드에서는 제목·이모지·별도 테두리 없이 표시한다. 목록 아래에는 stdio의 명령어와 전체 인자 또는 HTTP URL을 표시한다.
- 앱 실행 중 페이지 재진입과 Scope 전환 시 도구 캐시 유지, 캐시가 없는 서버의 자동 연결 확인, 설정 변경·삭제 시 캐시 제거와 진행 중 확인 취소를 확인. 모든 MCP 모달의 Select는 공유 UI를 사용하며, 모달 위에 표시되는 메뉴와 키보드 선택을 확인한다. Import 모달의 대상은 페이지의 현재 Scope를 따른다.
- 비밀값을 조회하지 않고 유지·교체·행 삭제, 값 이름 변경, 교체 입력을 지운 뒤 기존 값 유지.
- 등록 상태를 연결 성공과 구분하고 서버별 전달 제외 이유를 스레드에서 확인.
- 열린 대화에서 설정 변경 안내가 표시되고, 진행 중인 작업을 유지하며 작업 종료 후 재연결 가능.
- 설정 파일을 잘못 편집하면 마지막 정상 목록과 수정할 파일 경로를 유지하고, 복구하면 새 스냅샷 반영.

현재 구현 검증에서 자동화 suite와 macOS Keychain·loopback HTTP 테스트는 통과했다. Mac이 잠겨 있어 네이티브 UI의 테마·시각적 접근성 확인은 완료하지 못했다.

## 탐색·가져오기·독립 연결 확인

`mcp::tests::import`는 Claude Code·Desktop·Cursor·Codex·Zed 형식, JSONC 주석과 마지막 쉼표, 손상·없는 원본, 지원하지 않는 전송·옵션·변수, 부분 실패, 명시적 충돌 처리, 전역·프로젝트 대상, 비활성 등록, 비밀값 분리와 원본 bytes 보존을 검증한다. 원본 입력과 토큰은 오류·검토 응답에 되돌려 보내지 않는다. 기존 저장 경계의 자격 증명 실패·롤백 검증도 함께 사용한다.

`mcp::tests::check_http`는 실패·취소·시간 초과 후에도 HTTP DELETE가 완료된 뒤 결과가 반환되는지 검증한다.

`mcp::tests::check`는 실제 stdio MCP fixture로 initialize와 tools/list, 빈 도구 목록과 도구 기능 없는 서버, 실행 실패, 시간 초과와 취소, 자식 회수, 비활성 상태 및 설정 파일 불변을 확인한다. HTTP 확인은 다음 명령으로 임시 loopback 서버의 실제 헤더 인증·도구 조회·인증 실패와 세션 종료를 확인한다.

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib mcp::tests::check::http_check -- --ignored
cargo test --manifest-path src-tauri/Cargo.toml --lib mcp::tests::check_http -- --ignored
```

`McpsPage.test.tsx`는 명시적 확인과 화면 종료 취소·늦은 결과 무시, 파일 내용을 Configuration에 채우기, 저장 시 현재 내용 검증·가져오기, 충돌 시 오류와 이름 수정, 자동 활성화·재연결 금지를 검증한다.

카드에서 편집 모달 열기, 카드 새로고침 결과를 도구 목록 영역에 표시하기, 모달에서 제거 확인 후 닫기도 검증한다. 저장 성공 후 자동 연결 확인과 도구 갱신, 저장 실패 시 연결 확인 생략, 자동 확인 중 범위 변경 시 취소·늦은 결과 무시, 토글 변경 후 도구 목록 유지도 검증한다. 합성 데이터를 사용하는 임시 브라우저 harness에서 밝은·어두운 테마의 단일 열 카드, 도구 목록, 토글 독립 조작, 하단 제거·취소·저장 버튼 정렬을 확인했다.

네이티브 UI에서는 전역·프로젝트 대상 변경, 네이티브 파일 선택 및 취소, 파일 내용 불러오기와 취소 시 입력 유지, Configuration 수정 후 저장, 이름 충돌 오류, 가져오기 일부 실패 후 재시도, 확인 취소와 페이지 이동을 밝은·어두운 테마 및 키보드로 확인한다. 03번 구현 중 Mac이 잠겨 있어 네이티브 UI 검증은 수행하지 못했다.

## OAuth와 ACP 인증 중계

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib mcp::tests::oauth -- --ignored
cargo run --manifest-path src-tauri/Cargo.toml --example mcp-oauth-fixture
```

OAuth suite는 실제 loopback OAuth·MCP 서버와 메모리 자격 증명 저장소를 사용한다. SDK가 생성한 S256 PKCE를 서버에서 검증하고 동적·사전 등록, callback state·issuer 오류, 취소, 키체인 정리 실패, 재시작 복원, 동시 refresh와 회전 저장, refresh 거절, 범위·URL·issuer 격리, 로그아웃을 확인한다. URL 편집 뒤에도 기존 연결이 로그아웃으로 무효화되어야 한다. 알림·취소·열린 SSE 전달과 로그아웃에 따른 스트림 종료도 확인한다.

리뷰 회귀 테스트는 서로 다른 중계의 session ID 혼용 거절, JSON 응답 대기 중 stdio 취소 전달과 후속 요청, stdout을 읽지 않는 에이전트의 backpressure 중 연결 종료, 손상된 설정 파일의 로그아웃, 키체인 삭제 실패 후 접근 차단과 재시도, 인증 변경 시 재연결 revision 변경을 확인한다. 기본 suite의 스냅샷 테스트는 자격 증명 조회 중 설정 파일이 외부 수정되어도 한 연결에 서로 다른 설정이 섞이지 않는지 확인한다.

같은 suite에서 실제 Atte 실행 파일을 빌드하여 `--mcp-stdio-bridge`로 실행한다. stdin을 유지한 채 연결을 종료해도 브리지가 제한 시간 안에 종료되는지 확인한다. ACP fixture는 세션별 MCP 설정을 유지하고 HTTP 지원 여부 두 경우 모두 new/load/resume 뒤 실제 도구를 호출한다. 한 스레드를 재연결한 뒤 다른 스레드에서도 도구를 호출하여 공유 에이전트 프로세스와 연결 격리를 확인한다. 테스트용 실행 파일 경로만 실제 빌드 산출물로 주입하며 제품은 Tauri를 실행한 앱 경로를 사용한다.

예제는 URL 한 줄만 출력하고 합성 인증 정보만 발급하는 수동 UI 검증용 서버다. MCPs에서 출력된 URL과 OAuth를 등록하면 시스템 브라우저가 로컬 callback으로 돌아온다. 종료 시 프로세스를 중단하고, 앱에서 로그아웃한 뒤 테스트용 등록을 삭제한다. 실제 계정·외부 OAuth 서비스·사용자 API 키는 사용하지 않는다.

04번 구현 중 macOS debug 번들에서 등록, 시스템 브라우저 로그인, 키체인 저장, 앱 종료·재시작 후 인증 복원, 복원된 인증으로 도구 목록 조회, 로그아웃과 이후 접근 거절을 확인했다. 밝은 테마의 OAuth 카드와 키보드 로그인, 어두운 테마 전환을 확인했다. 네이티브 자동화의 팝업 조작이 불안정하여 어두운 테마는 같은 Solid 컴포넌트와 스타일을 사용하는 임시 브라우저 harness에서 추가 확인했다. 네 인증 상태·로그인/취소/로그아웃·발견 실패 오류와 OAuth 편집 폼·저장소 오류의 대비와 레이아웃을 확인했다. harness는 `.scratch/`에만 두며 제품에 포함하지 않는다. 테스트용 서버를 제거하고 원래 테마를 복원했다.

## MCP 폼 레이아웃

Import servers에서는 Configuration 라벨과 같은 줄 오른쪽의 Choose로 파일 원문을 입력창에 채운다. 파일 선택에서는 파싱하거나 저장하지 않는다. 입력창은 직접 편집할 수 있으며 Save에서 현재 내용의 형식·지원 여부·이름 충돌을 검증하고 모든 서버를 비활성으로 가져온 뒤 모달을 닫는다. Review 버튼과 원본·후보 박스는 표시하지 않는다. 오류는 입력창 아래 빨간 글씨로 표시하며 입력을 유지한다. 기존 서버와 충돌하면 Configuration에서 이름을 바꿔야 한다. 일부 저장 실패 시 같은 입력으로 다시 Save하면 실패한 서버만 재시도한다. 전역 설정 자동 탐색 진입점은 제공하지 않는다. 이 흐름은 `McpsPage.test.tsx`에서 검증한다.

MCP 폼의 Select는 최소 높이 44px이며 현재 값과 옵션 모두 14px 글자를 사용한다. 라벨과 입력창은 8px 레이아웃 간격을 두고, 좁은 창에서는 환경변수·헤더 이름과 값 유형을 세로로 배치한다. 가져오기·추가·편집 모달은 창 가장자리에서 16px 여백을 유지하며 본문을 스크롤해 하단 동작 버튼에 접근한다.

임시 브라우저 harness에서 실제 컴포넌트로 밝은·어두운 테마 및 창 너비 400·640·1050px에서 세 모달의 경계, 폼 간격, Select 높이와 글자 크기를 측정했다. Chromium 검증이며 WebKit 실행 파일이 없어 네이티브 WebView의 시각 검증은 수행하지 못했다.

Configuration/Choose 변경 후 같은 Chromium harness에서 밝은·어두운 테마 및 너비 400·640·1050px의 라벨·버튼 수평 정렬, 버튼 우측 정렬, 파일 내용 채우기, Save 오류 표시·입력 유지와 저장 후 닫기를 확인했다. UI 테스트 19개와 Rust 가져오기 테스트 8개, 타입 검사·Biome·FSD·Rust 포맷·Clippy 검사를 통과했다. 네이티브 파일 선택창의 실제 조작은 별도 수동 확인 대상이다.

## 값 행과 자동 도구 확인

HTTP headers와 Environment variables의 Name 입력과 Value type Select는 라벨 줄 높이 20px, 입력 높이 44px로 정렬한다. 각 행의 삭제는 우측 상단 휴지통 버튼이며, 행 추가는 + 버튼이다. 아이콘 버튼의 접근 가능한 이름과 툴팁은 각각 Delete와 Add value의 번역을 사용한다. 좁은 창에서는 이름과 유형이 세로로 배치된다.

MCPs 진입과 Scope 전환 시 현재 설정과 일치하는 도구 캐시가 없는 서버는 활성 여부와 관계없이 자동 연결 확인한다. 연결 성공과 빈 도구 목록은 캐시하며, 오류 결과는 같은 페이지 방문 중 반복 확인하지 않고 다음 진입 때 재시도한다. 스냅샷 갱신은 진행 중인 같은 설정의 확인을 중복 시작하지 않는다. 설정 변경·삭제·페이지 종료·Scope 전환 때는 해당 확인을 취소하며 늦은 결과를 반영하지 않는다. 서버를 활성화하거나 스레드를 재연결하지 않는다.

UI 테스트에서 자동 확인·캐시 재사용·빈 목록 캐시·실패 후 재진입·삭제 후 재추가·범위 변경과 늦은 결과 무시, 두 전송 유형의 +/휴지통 행 조작을 검증한다. 임시 Chromium harness에서 밝은·어두운 테마와 너비 400·640·1050px의 입력 높이·수평 정렬·휴지통 위치와 행 추가·삭제를 확인한다.

## 카드 새로고침과 OAuth

Check connection은 카드의 on/off 토글 왼쪽 새로고침 아이콘이다. 확인 중에는 취소 아이콘으로 바뀐다. 성공하면 카드에 도구 목록이 표시되고, 실패나 취소 시 같은 위치에 원인을 표시한다. 편집 모달에는 연결 확인·Sign in·인증 상태 박스를 표시하지 않는다.

사용자가 Save 또는 카드 새로고침(Check connection)을 직접 누른 경우에만 OAuth 인증 필요 시 로그인 흐름을 시작하며, 로그인 성공 후 연결 확인을 한 번 더 실행해 도구를 채운다. 확인 취소·페이지 종료·범위 변경·설정 변경·삭제 때 OAuth 로그인도 취소하고 늦은 완료를 반영하지 않는다. 로그인 실패는 도구 영역에 표시하며 스냅샷 갱신만으로 반복 로그인하지 않는다.

인증된 OAuth 서버와 재인증이 필요한 서버의 편집 모달에는 Uninstall 바로 오른쪽에 Sign out이 표시된다. Uninstall·Sign out·Cancel·Save는 모두 공유 Button의 기본 높이 40px를 사용한다. 좁은 창에서는 왼쪽·오른쪽 버튼 묶음이 줄바꿈된다. 페이지 진입·Scope 전환·설정 스냅샷 갱신에 따른 자동 확인에서는 인증 필요 상태만 표시하고 로그인하지 않는다. 자동 확인 중 Save를 직접 누르면 진행 중인 같은 요청에 로그인 허용을 반영한다. 로그아웃 시 도구 캐시를 지우며 자동 로그인하지 않는다. 카드의 새로고침으로 다시 로그인할 수 있다.

이 변경은 UI 테스트 31개와 타입·Biome·FSD 검사를 통과했다. 페이지 진입·Scope 전환·재진입 때 로그인하지 않으며, Save로 시작한 확인과 진행 중 자동 확인에 대한 Save 모두 필요한 로그인을 수행하는지 검증한다. 임시 Chromium harness에서 밝은·어두운 테마 및 창 너비 400·640·1050px의 새로고침·토글 수평 정렬, 카드 새로고침의 모달 비개방, 하단 네 버튼 높이 40px와 순서·좁은 창 줄바꿈을 확인했다. 실제 OAuth 브라우저 로그인은 기존 백엔드를 사용하며 이번 검증은 합성 응답을 사용했다.

## 스레드 MCP 정보

스레드 정보(Thread Info)의 Context 아래 MCP 섹션에서 현재 연결에 적용된 활성 서버와 연결 준비 중 문제가 발생한 서버를 이름순으로 확인한다. 비활성 서버는 제외한다. 서버가 없으면 `없음`, 연결 정보를 아직 받지 못했으면 `정보 없음`으로 구분한다. 설정 파일 전체 오류는 서버 이름 대신 안내문으로 표시한다.

서버 목록은 최대 5행까지 늘어나고 이후 목록 영역만 세로 스크롤한다. 긴 이름은 말줄임 처리하며 hover로 전체 이름을 확인한다. 문제 서버는 이름 오른쪽의 원형 느낌표에 hover하거나 키보드 포커스를 이동하면 사유가 표시된다. MCP 제목 오른쪽 화살표 버튼으로 MCPs 페이지를 연다. 이 박스에는 설정 변경 안내와 재연결 버튼을 표시하지 않는다. 재연결 전까지 기존 연결의 서버 목록을 유지한다. 스레드 상단에는 MCP 배너를 표시하지 않는다.

회귀 검사에서는 서버 없음·정보 미수신·정상과 문제 서버 혼합·비활성 제외, 6개 이상 목록의 스크롤, 긴 이름과 사유, 키보드 툴팁, 재연결 후 갱신과 스레드 전환을 확인한다. 밝은 테마와 어두운 테마에서도 동일하게 읽을 수 있어야 한다. 목록의 각 행은 24px로 표시하며 최대 5행(120px) 이후 스크롤한다. MCPs 이동 버튼은 작업 실행 중에도 사용할 수 있으며 스레드를 재연결하지 않는다.
